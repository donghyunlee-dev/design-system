# 템플릿 선택 가이드

> "어떤 화면을 만들 때 어떤 템플릿을 써야 하는가"를 결정하는 기준입니다. 컴포넌트 자체 사용법은 [USAGE.md](./USAGE.md), 배포 전 체크리스트는 [CHECKLIST.md](./CHECKLIST.md)를 참고하세요.

이 디자인 시스템은 두 축을 지원합니다 ([README.md](./README.md#두-축-기간계-시스템--일반-웹사이트) 참고).

- **기간계 시스템** (내부 업무 화면) → [1부: `business/admin` 템플릿](#part-1-기간계-시스템-businessadmin)
- **일반 웹사이트** (외부 사용자 대상 서비스) → [2부: `service` 템플릿](#part-2-일반-웹사이트-service)

축을 먼저 못 정하겠다면 아래 0부를 먼저 읽으세요.

---

## Part 0. 요구사항(PRD)에서 축·템플릿 판단하기

화면을 만들기 전에 받는 요구사항(PRD, 티켓, 채팅으로 받은 요청 등)에는 보통 "누가 쓰는지"와 "무엇을 하는지"가 들어있습니다. 아래 신호로 축을 먼저 정하고, 그다음 Part 1/2의 시나리오 표에서 세부 템플릿을 고릅니다.

### 축 판단 신호

| 요구사항에 이런 신호가 있으면 | 축 |
|---|---|
| "사내", "관리자", "직원", "결재/승인", "재고/발주/정산" 등 회사 내부 업무 언급 | 기간계 (Part 1) |
| 로그인한 사내 사용자만 접근, 외부 노출 없음 | 기간계 (Part 1) |
| "고객", "회원가입", "구매", "홍보", "소개" 등 외부 사용자 대상 언급 | 일반 웹사이트 (Part 2) |
| 검색엔진 노출·마케팅 성과(전환율, 가입률)가 목표로 언급됨 | 일반 웹사이트 (Part 2) |

두 신호가 섞여 있으면(예: "협력사가 접속하는 발주 포털") **로그인 이후 화면은 기간계 기준, 로그인 이전 화면(가입 유도 등)은 일반 웹사이트 기준**으로 나눠서 판단하세요. 하나의 화면에 두 축의 톤을 동시에 섞지 않는 것이 [CHECKLIST.md](./CHECKLIST.md)와 [loop/policy.md](./loop/policy.md) 3항의 원칙입니다.

### 축 안에서 템플릿 판단 (조건부 규칙)

축이 정해지면, PRD에 아래 조건이 있는지로 세부 템플릿을 좁힙니다.

- `필수: 검색/필터` → `ListSearchTable` (Part 1)
- `필수: 결재선/승인 단계` → `ApprovalView`, 순서 없이 상태만 바뀌면 `KanbanBoard` (Part 1)
- `필수: 실시간 갱신` → `MonitoringBoard`, 정적 요약이면 `DashboardKPI` (Part 1)
- `필수: 인쇄/출력` → `ReportLayout` 또는 `DocumentPrint` (Part 1)
- `필수: 결제` → `CheckoutForm` (Part 2)
- `필수: 회원가입 단계` → `SignupPage`, 단순 로그인이면 `LoginSimple`/`LoginSplit` (Part 2)
- `필수: 이미지 중심 상품 탐색` → `ProductGrid`, 스펙/텍스트 비교 중심이면 `ProductList` (Part 2)

이 규칙에 없는 새로운 조건이 반복해서 나온다면, 즉흥적으로 새 템플릿을 만들기보다 이 표에 규칙을 먼저 추가하고 기존 템플릿에 prop을 확장할 수 있는지부터 검토합니다.

## Part 1. 기간계 시스템 (`business`/`admin`)

### 1. `admin/*` vs `business/*` — 먼저 이것부터 결정

`src/templates/`에는 비슷해 보이는 화면이 두 세트로 나뉘어 있습니다.

| 상황 | 선택 |
|---|---|
| 검색·필터·페이지네이션 없이 단순 목록/폼/대시보드만 필요 | `admin/DataTablePage`, `admin/DataFormPage`, `admin/DashboardStats`, `admin/DashboardFull` |
| 검색·필터·다단계 등록·승인 이력 등 실제 업무 로직이 들어감 | `business/*` (30여 종) |

**안티패턴**: `admin/DataTablePage`로 시작한 뒤 검색창·필터를 직접 붙이지 마세요. 검색/필터가 필요하다는 걸 아는 순간 바로 `business/ListSearchTable`로 시작하는 것이 중복 구현을 피하는 길입니다. (`ListSearchTable`은 `DataTablePage` + 검색/필터/페이지네이션을 합친 상위 호환입니다.)

---

### 2. 업무 시나리오별 템플릿

### 목록 / 조회

| 템플릿 | 사용 시점 | 피해야 할 것 |
|---|---|---|
| `ListSearchTable` | 검색·필터가 있는 일반 목록 (주문 목록, 상품 목록 등) | 검색 없는 화면에 억지로 필터 UI를 붙임 |
| `MasterDetail` | 좌측 목록 클릭 시 우측에 상세가 즉시 바뀌는 화면 (메일함, 설정 항목) | 상세 전환에 페이지 이동(라우팅)을 사용 — 좌우 분할의 장점을 잃음 |
| `GlobalSearchResults` | 여러 데이터 타입을 한 번에 검색하는 통합 검색 결과 | 단일 타입 목록에 그룹 헤더를 억지로 추가 |
| `DocumentCatalog` | 카테고리별로 분류된 문서/양식 모음 | 카테고리 없이 단일 목록일 때 사용 (`ListSearchTable`이 더 적합) |
| `FileExplorer` | 폴더 트리 탐색이 필요한 파일 관리 화면 | 폴더 구조가 없는 단순 첨부파일 목록에 사용 |

### 등록 / 입력

| 템플릿 | 사용 시점 | 피해야 할 것 |
|---|---|---|
| `FormRegister` | 섹션별로 구분된 단일 페이지 등록 폼 | 입력 단계가 서로 의존적(다음 단계가 이전 값에 따라 바뀜)인 경우 |
| `WizardForm` | 단계별로 진행하며 이전 입력에 따라 다음 단계가 달라지는 등록 | 단계 이동 없이 한 화면에서 끝나는 짧은 폼 |
| `BulkImport` | 엑셀/CSV 업로드 → 컬럼 매핑 → 검증 → 반영의 대량 등록 | 몇 건 안 되는 데이터를 대량 업로드 UI로 처리 |

### 승인 / 워크플로우

| 템플릿 | 사용 시점 | 피해야 할 것 |
|---|---|---|
| `ApprovalView` | 단계별 결재선이 있는 승인 화면 | 결재선 없이 단순 상태(대기/완료)만 있는 경우 (`StatusBadge`로 충분) |
| `KanbanBoard` | 상태별 컬럼 간 드래그 이동이 자연스러운 작업(업무 진행 단계) | 순서가 고정된 결재/승인 흐름에 사용 (`ApprovalView`가 더 적합) |
| `InboxCenter` | 처리해야 할 항목이 쌓이는 수신함형 화면 (알림함, 요청함) | 단순 알림 목록일 뿐 처리 액션이 없는 경우 |

### 대시보드 / 모니터링

| 템플릿 | 사용 시점 | 피해야 할 것 |
|---|---|---|
| `DashboardKPI` | 핵심 지표 카드 중심의 요약 대시보드 | 실시간 갱신이 필요한 운영 모니터링 (`MonitoringBoard`가 더 적합) |
| `MonitoringBoard` | 여러 지점/설비 등 실시간 상태를 감시하는 화면 | 단순 통계 요약만 필요한 경우 (불필요하게 무거움) |
| `ReportLayout` | 인쇄/공유를 전제로 한 정적 리포트 | 실시간으로 값이 바뀌는 대시보드에 사용 |

### 이력 / 비교

| 템플릿 | 사용 시점 | 피해야 할 것 |
|---|---|---|
| `DetailView` | 단일 항목의 상세 정보 + 변경 이력 | 두 항목/버전을 나란히 비교해야 하는 경우 |
| `ActivityTimeline` | 시간순으로 발생한 이벤트를 나열 | 이벤트 간 필드 단위 차이를 보여줘야 하는 경우 (`DiffView`가 적합) |
| `DiffView` | 두 버전/문서 간 필드 단위 변경 사항 비교 | 단순 시간순 로그 표시 (`ActivityTimeline`이 적합) |

### 기타

| 템플릿 | 사용 시점 |
|---|---|
| `ScheduleCalendar` | 날짜/시간 기준 일정 배치 화면 |
| `SettingsPage` | 좌측 메뉴 + 우측 설정 항목 구성의 설정 화면 |
| `DocumentPrint` | 인쇄 전용 레이아웃(거래명세서, 견적서 등) |

### 3. 새 템플릿을 추가할 때

기존 30여 종 중 80% 이상 겹치는 템플릿이 있다면 새로 만들지 말고 기존 템플릿에 prop을 추가하세요. 완전히 새로운 상호작용 패턴(예: 지도 기반 화면, 실시간 채팅)일 때만 신규 템플릿을 추가하고, 이 표에 사용 시점과 안티패턴을 함께 기록합니다.

## Part 2. 일반 웹사이트 (`service`)

외부 사용자가 직접 접하는 서비스 화면입니다. 기간계 화면과 달리 첫인상·전환율이 중요하므로, 같은 `Button`/`Card` 컴포넌트를 쓰더라도 카피·여백·CTA 배치에 더 신경 씁니다.

### 랜딩 (`service/landing`)

| 템플릿 | 사용 시점 | 피해야 할 것 |
|---|---|---|
| `LandingCentered` | 로고+내비+뱃지+헤드라인이 중앙 정렬된 표준 랜딩 | 좌우 비대칭 비주얼(제품 스크린샷 등)이 핵심일 때 (`LandingSplit`이 적합) |
| `LandingSplit` | 좌측 카피/CTA + 우측 제품 이미지·스크린샷 분할 구성 | 보여줄 비주얼 자산이 없는 경우 (빈 여백만 남음) |
| `LandingMinimal` | 카피 중심, 장식 최소화된 극단순 랜딩 (eyebrow+헤드라인+CTA) | 기능이 많아 섹션 여러 개로 설명해야 하는 제품 |

### 인증 (`service/auth`)

| 템플릿 | 사용 시점 | 피해야 할 것 |
|---|---|---|
| `LoginSimple` | 이메일/비밀번호 중심의 단순 로그인 | 브랜드 스토리텔링이 필요한 B2C 서비스 (`LoginSplit`이 적합) |
| `LoginSplit` | 브랜드 이미지/설명을 곁들인 로그인 (마케팅 성격이 강한 서비스) | 사내 관리자 로그인처럼 브랜딩이 불필요한 경우 (`LoginSimple`로 충분) |
| `SignupPage` | 단계(`steps`)가 있는 회원가입 | 단일 입력만으로 끝나는 가입 (과한 단계 UI) |

### 카탈로그 (`service/catalog`)

| 템플릿 | 사용 시점 | 피해야 할 것 |
|---|---|---|
| `ProductGrid` | 이미지 중심 카드 그리드로 상품을 훑어보는 화면 | 텍스트 정보(스펙 비교 등)가 중요한 목록 (`ProductList`가 적합) |
| `ProductList` | 좌측 필터 + 우측 리스트형 상품 목록 | 이미지 임팩트가 중요한 비주얼 상품(패션, 인테리어 등) |
| `ProductDetail` | 이미지+가격+설명이 있는 단일 상품 상세 | 여러 상품을 한 번에 비교해야 하는 화면 |

### 결제 / 계정 (`service/commerce`, `service/account`)

| 템플릿 | 사용 시점 | 피해야 할 것 |
|---|---|---|
| `CheckoutForm` | 주문 항목 + 배송 정보 입력 + 결제 확정 | 결제가 없는 단순 정보 제출 폼 (`FormRegister`가 적합) |
| `SettingsSidebar` | 설정 항목이 많아 좌측 사이드바 탐색이 필요한 계정 설정 | 설정 항목이 3~4개 이하로 적은 경우 (`SettingsTabs`가 더 가벼움) |
| `SettingsTabs` | 설정 항목이 적어 탭 전환으로 충분한 계정 설정 | 설정 항목이 많아 탭이 한 화면에 다 안 들어가는 경우 |

### 기간계와 다른 판단 기준

| 항목 | 기간계 (`business`/`admin`) | 일반 웹사이트 (`service`) |
|---|---|---|
| 우선순위 | 정보 밀도, 작업 처리 속도 | 첫인상, 전환(가입/구매) |
| 색상 사용 | `--color-brand`는 액션에만 절제해서 사용 | 헤드라인·CTA에 브랜드 색을 과감히 노출 |
| 여백 | 좁게, 한 화면에 많은 정보 | 넓게, 시선을 헤드라인/CTA로 유도 |
| 실패 시 되돌아갈 템플릿 | `DataTablePage`/`DataFormPage` (가장 단순한 형태) | `LandingMinimal` (가장 단순한 형태) |
