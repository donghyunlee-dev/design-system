## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했습니다. 정책 7항에 따라 사람이 등록했거나 평가에서 발견된 갭 항목은 벤치마크 순회보다 우선 소비해야 하기 때문입니다. 검토 결과 B001~B015가 모두 "완료" 상태이며 "대기" 항목이 하나도 없어, benchmark-suite 고정 목록을 cursor 순서대로 소비합니다.

`docs/loop/benchmark-suite.md`의 frontmatter cursor 값은 2이고 표는 10개 행(BM01~BM10)이므로, 0-based 인덱스 2에 해당하는 **BM03 — GitHub 검색 결과**(https://github.com/search?q=react&type=repositories, 패턴: 검색 결과)를 오늘의 벤치마크로 선택합니다. 직전 사이클(2026-09-08, BM02)에서 cursor를 2로 갱신했으므로 이번 사이클은 그 다음 항목을 이어서 처리합니다(정책 7항 회귀 순회). 처리 후 cursor는 (2+1) % 10 = 3으로 갱신했습니다.

BM03은 검색어에 대한 저장소 검색 결과 화면으로, 상단 검색 입력 + 좌측 패싯 필터(언어·정렬 등) + 결과 건수 헤더 + 각 결과 행(저장소명·설명·주요 언어·스타 수·업데이트 시각·토픽 태그)을 담은 "검색 결과" 패턴에 해당합니다. 구조적으로는 기간계(business/admin)의 통합 검색·목록 조회 화면(예: 기존 GlobalSearchResults(B007), FacetedSearchResults, ListSearchTable)과 재활용 축이 겹치므로, 재현·평가 시 다음 정책 가드레일을 유의합니다.

- 정책 3항(축 분리): 이 패턴이 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단하고, 그 축 안에서 이미 있는 패턴과 겹치지 않는 갭만 채택합니다. BM03은 데이터 조회·필터 중심의 검색 결과이므로 기간계(business) 축의 검색/리스트 자산과 대조하며, 두 축을 뒤섞은 패턴은 채택하지 않습니다.
- 정책 2항(중복 금지, DRY): 신규 작업에 앞서 `src/components/`·`src/templates/`(특히 기존 GlobalSearchResults(B007), FacetedSearchResults, ListSearchTable, Table/Tag/ColorTag/StatusBadge/Pagination 등 검색·필터 자산)를 대조해 목적이 겹치는 자산이 이미 있는지 확인한 뒤에만 추가 범위를 확정합니다. 목적이 겹치는 기존 패턴이 있으면 반복 채택하지 않습니다.
- 정책 8항(갭 승격 기준): 발견된 부족 항목을 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap으로 판정된 경우에만 컴포넌트/토큰을 추가합니다. execution-issue는 시스템을 변경하지 않고 리포트에만 기록합니다.
- 정책 9항(일관성 유지): 업그레이드가 필요하더라도 전체 컨셉·스타일을 유지하는 범위 내 추가만 허용하며, 기존 시맨틱 토큰 체계 밖의 색상값 하드코딩이나 새로운 스타일링 체계 도입은 금지합니다.
- 정책 5항(병합 게이트): 모든 변경은 `develop` 대상 PR로만 제출하며, `main`/`develop` 직접 push는 금지합니다.

benchmark-suite 항목을 선택했으므로 `docs/loop/backlog.md`의 status는 이번 사이클에서 변경하지 않으며, benchmark-suite의 cursor만 2에서 3으로 갱신했습니다.
