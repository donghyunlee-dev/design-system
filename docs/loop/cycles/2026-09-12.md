## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했습니다. 정책 7항에 따라 사람이 등록했거나 평가에서 발견된 갭 항목은 벤치마크 순회보다 우선 소비해야 하기 때문입니다. 검토 결과 B001~B015가 모두 "완료" 상태이며 "대기" 항목이 하나도 없어, benchmark-suite 고정 목록을 cursor 순서대로 소비합니다.

`docs/loop/benchmark-suite.md`의 frontmatter cursor 값은 3이고 표는 10개 행(BM01~BM10)이므로, 0-based 인덱스 3에 해당하는 **BM04 — Trello 템플릿 갤러리**(https://trello.com/templates/business, 패턴: 카드 그리드/템플릿)를 오늘의 벤치마크로 선택합니다. 직전 사이클(2026-09-09, BM03)에서 cursor를 3으로 갱신했으므로 이번 사이클은 그 다음 항목을 이어서 처리합니다(정책 7항 회귀 순회). 처리 후 cursor는 (3+1) % 10 = 4로 갱신했습니다.

BM04는 업무 목적별로 분류된 보드 템플릿을 카드 그리드로 진열하고, 각 카드에 미리보기 이미지·제목·제작자·카테고리 태그를 담아 선택·복제할 수 있게 하는 "카드 그리드/템플릿" 갤러리 패턴에 해당합니다. 구조적으로는 카드 진열·미리보기·복제 액션 중심의 화면으로, 재현·평가 시 다음 정책 가드레일을 유의합니다.

- 정책 3항(축 분리): 이 패턴이 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단하고, 그 축 안에서 이미 있는 패턴과 겹치지 않는 갭만 채택합니다. BM04는 템플릿 카탈로그·갤러리 성격이므로, 두 축을 뒤섞은 패턴(예: 사내 도구에 마케팅 랜딩식 화려한 모션을 그대로 적용)은 채택하지 않습니다.
- 정책 2항(중복 금지, DRY): 신규 작업에 앞서 `src/components/`·`src/templates/`(특히 기존 카드 그리드/갤러리 자산 — MediaCard, MediaCardHoverActions(B012), Notion/Figma 등 과거 카드 그리드 재현 결과물, Grid/Card/Tag/ColorTag/Avatar 등)를 대조해 목적이 겹치는 자산이 이미 있는지 확인한 뒤에만 추가 범위를 확정합니다. 목적이 겹치는 기존 패턴이 있으면 반복 채택하지 않습니다.
- 정책 8항(갭 승격 기준): 발견된 부족 항목을 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap으로 판정된 경우에만 컴포넌트/토큰을 추가합니다. execution-issue는 시스템을 변경하지 않고 리포트에만 기록합니다.
- 정책 9항(일관성 유지): 업그레이드가 필요하더라도 전체 컨셉·스타일을 유지하는 범위 내 추가만 허용하며, 기존 시맨틱 토큰 체계 밖의 색상값 하드코딩이나 새로운 스타일링 체계 도입은 금지합니다.
- 정책 5항(병합 게이트): 모든 변경은 `develop` 대상 PR로만 제출하며, `main`/`develop` 직접 push는 금지합니다.

benchmark-suite 항목을 선택했으므로 `docs/loop/backlog.md`의 status는 이번 사이클에서 변경하지 않으며, benchmark-suite의 cursor만 3에서 4로 갱신했습니다.

## 완성도 평가

- **벤치마크**: Trello 템플릿 갤러리 (https://trello.com/templates/business)
  - 참고: 세션 환경의 아웃바운드 프록시가 조직 정책으로 `trello.com`에 대한 CONNECT를 거부(403)하여, 이번 사이클에서는 벤치마크 사이트 스크린샷을 직접 캡처할 수 없었습니다. 아래 평가는 자사 구현 스크린샷과 기존 정책 문서·백로그에 기록된 BM04 패턴 설명(카드 그리드/미리보기/제작자·카테고리 태그/복제 액션)을 근거로 진행했습니다.
  - 구현 스토리: `Templates/Business` / `Template Gallery (Spotlight)` (export: `TemplateGallerySpotlightHome`, id: `templates-business--template-gallery-spotlight-home`)

- **점수 (1~5점)**
  - layout: 4 — 상단 밑줄형 탭(전체/ERP/OMS/WMS/PRM/그룹웨어) → 대형 "주요 추천" 카드 행 → 하단 일반 그리드로 이어지는 구조가 템플릿 갤러리의 위계(추천 강조 + 카테고리 탐색)를 잘 재현함.
  - componentFidelity: 3 — 카드에 실제 미리보기 썸네일 대신 이모지 아이콘 폴백만 사용했고, "인기"/"신규" 배지가 모두 동일한 회색 `Tag`로만 표시되어 유형 구분이 약함.
  - typography: 4 — 제목/설명/본문 위계와 여백(`mb-1`, `mb-5`, `mb-10` 등)이 기존 타이포 스케일과 일관됨.
  - interaction: 2 — 카드에 호버 시 미리보기·강조 등의 상태 변화가 전혀 없고, "이 템플릿 사용" 버튼이 항상 고정 노출되어 Trello류 갤러리 특유의 호버 인터랙션이 빠짐.
  - brandTone: 4 — 색상·라운딩·버튼 스타일이 기존 시맨틱 토큰과 일관되며 한국어 로컬라이징(부서명, 문구)도 자연스러움.

- **갭 목록**
  1. **[execution-issue]** 카드 호버 인터랙션 부재 — `src/components/data/MediaCardHoverActions.tsx`에 카드 호버 시 오버레이 액션을 보여주는 컴포넌트가 이미 존재하지만(`B012`에서 이 목적으로 추가됨), 이번 `TemplateGallerySpotlight.tsx` 구현은 이를 사용하지 않고 `MediaCard`만 사용해 정적으로 렌더링함. 실제로 `src/components/data/`를 확인한 결과 해당 컴포넌트가 존재함을 확인했으므로 design-system-gap이 아님.
  2. **[execution-issue]** 배지 색상 구분 부재 — `src/components/data/ColorTag.tsx`에 variant(`brand`/`success`/`warning`/`danger`/`info`)별 색상을 지원하는 컴포넌트가 이미 존재하지만, 이번 구현은 `Tag`(항상 중립 회색)만 사용해 "인기"와 "신규" 배지가 시각적으로 구분되지 않음. `src/components/data/`를 확인해 `ColorTag`가 이미 존재함을 확인했으므로 design-system-gap이 아님.
  3. **[execution-issue]** 썸네일 이미지 미사용 — `MediaCard`가 `image`/`thumbnailSrc` prop을 지원함에도 스토리 데이터에 실제 이미지 URL을 전달하지 않아 모든 카드가 이모지 아이콘 폴백으로만 표시됨. 컴포넌트 자체의 한계가 아니라 스토리 데이터 구성의 문제.
