## 오늘의 스코프

오늘 사이클은 백로그의 유일한 대기 항목이자 사람이 직접 등록한(human-added) **B001 — Astryx Documentation Catalog 패턴 검토**만 진행합니다.

선정 근거:
- 우선순위 규칙상 human-added 항목이 pm-proposed보다 앞서며, 현재 대기 상태 항목은 B001 하나뿐입니다.
- 기존 `src/templates/business/`에는 목록(ListSearchTable), 상세(DetailView), 폼(FormRegister/WizardForm), 대시보드(DashboardKPI/MonitoringBoard), 승인(ApprovalView), 설정(SettingsPage), 리포트(ReportLayout), 마스터-디테일(MasterDetail)이 이미 존재하지만, **문서/매뉴얼 카탈로그(내부 위키·업무 매뉴얼·API 문서)** 성격의 레이아웃 템플릿은 부재합니다. 명확한 커버리지 갭입니다.
- 내부 업무 시스템에서 사이드바 목차 + 본문 + 우측 페이지 내 앵커 구조의 문서 카탈로그는 재활용 가치가 높아 정책 3항(내부 업무 시스템 적합성)에 부합합니다.
- 일일 스코프 상한(1~3개) 내에서 첫 실사이클인 만큼 단일 항목에 집중해 구현 품질을 확보합니다.

### 소견 (참고용 — 최종 판단 아님)

- 레이아웃 골격(좌측 사이드바 내비게이션 + 우측 본문 카드)은 Stripe Docs가 채택한 문서 카탈로그의 일반적인 구조와 방향이 일치합니다.
- Stripe Docs는 상단에 글로벌 내비게이션 바(제품군 탭, 검색, Ask AI, 로그인/계정)와 히어로 영역, 카드형 바로가기(Payments/Revenue/Developers), 인터랙티브 코드 예제를 포함해 정보 밀도와 시각적 진입점이 훨씬 다양합니다. 반면 우리 DocCatalog는 사이드바 카테고리 목록 + 단일 문서 본문(제목/메타/본문 텍스트)만으로 구성되어 있어 상대적으로 단순하고 정적인 느낌입니다.
- 우리 결과물의 사이드바는 카테고리 그룹핑(업무 가이드/API 문서/FAQ)과 검색 입력창을 갖추고 있어 내부 업무 매뉴얼·API 문서 카탈로그 용도로는 핵심 요소를 충족하는 것으로 보입니다. 다만 Stripe 대비 다음이 부족합니다.
  - 브레드크럼이나 현재 문서의 상위 카테고리 표시가 본문 영역에 없음
  - 코드/API 예제와 같은 리치 콘텐츠 블록 부재(현재는 텍스트/리스트 위주)
  - 상단 전역 검색·전환 내비게이션이 없어 다른 문서 영역으로의 빠른 이동 동선이 약함
- 위 차이는 내부 업무 시스템(사내 매뉴얼/위키) 맥락에서는 허용 가능한 수준의 단순화로 볼 수 있으나, 코드 예제가 포함된 API 문서(ERP 발주 API, WMS 재고 조회 API 등)를 다루는 경우 코드 블록 컴포넌트 추가를 검토할 필요가 있습니다.
- 이 비교는 참고용 소견이며, 실제 개선 여부·우선순위는 PM/디자인 리뷰에서 최종 판단합니다.
