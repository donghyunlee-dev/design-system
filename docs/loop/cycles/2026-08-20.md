## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했으나, B001~B013이 모두 "완료" 상태여서 대기 중인 사람 등록 항목이 없습니다. 따라서 정책 7항에 따라 `docs/loop/benchmark-suite.md`의 고정 목록을 cursor 순서대로 소비합니다.

현재 cursor 값은 4이고 표에 10개 행(BM01~BM10)이 있으므로, 0-based 인덱스 4번째 행인 **BM05 — Notion 템플릿 갤러리**(https://www.notion.so/templates, 패턴: 카드 그리드/갤러리)를 오늘의 벤치마크로 선택했습니다. 직전 사이클(2026-08-19)이 BM04를 소비하고 cursor를 4로 갱신한 순회의 다음 항목에 해당합니다.

선택 처리 후 benchmark-suite의 cursor 값을 (4 + 1) % 10 = **5**로 갱신했습니다(다음 사이클은 BM06 Zendesk Help Center).

정책 3항에 따라 이 페이지가 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단합니다. Notion 템플릿 갤러리는 상단 카테고리 네비게이션 + 카테고리별 섹션 헤더 + 템플릿 카드 그리드(썸네일·제목·작성자·카테고리 메타)로 구성된 카드 그리드/갤러리 패턴으로, 외부 사용자가 템플릿을 둘러보고 선택하도록 유도하는 서비스/카탈로그 성격이 강합니다. 다만 사내 기간계에서도 업무 양식·보고서 템플릿 갤러리로 재활용 여지가 있어, 재현·평가 단계에서 두 축 중 어느 쪽으로 재현할지 정책 3항 기준으로 확정합니다.

재현·평가 단계에서 기존 `src/components/`(MediaCard, CardMedia 등 카드 계열)와 `src/templates/`의 카드 그리드/갤러리 계열(Notion·Figma·Asana·Trello 재현 사이클에서 다뤄진 갤러리 템플릿 포함)을 대조해, 정책 2항(중복 금지)에 따라 목적이 겹치는 신규 템플릿은 추가하지 않습니다. 발견된 부족 항목은 정책 8항 기준으로 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap만 시스템 업그레이드 후보로 삼고 execution-issue는 리포트에만 기록합니다.

|---|---|---|
| layout | 4 | 헤더 + 검색 + 상단 카테고리 필터 + 추천 섹션 + 전체 그리드 구조가 Notion 템플릿 갤러리의 정보 구조와 유사하게 재현됨 |

| brandTone | 3 | 카드 커버에 `success`/`warning`/`danger` 등 상태 의미 토큰을 순수 장식용으로 섞어 써서, 리포트 자동화 카드에 "danger"(위험) 색이 붙는 등 의미 충돌이 발생하고 톤이 산만해짐 |

### 갭 목록

1. **[execution-issue]** 카드 썸네일에 `image`를 쓰지 않고 `cover` 단색만 사용함 — `CardMedia`(`src/components/data/CardMedia.tsx`)는 이미 `image` prop으로 실제 썸네일을 지원하는데, 이번 스토리(`automationGalleryItems`, `Business.stories.tsx`)는 전부 `cover` 색상만 지정해 활용하지 않음.
2. **[execution-issue]** 템플릿 카드에 클릭/미리보기 인터랙션이 없음 — `TemplateCard`(`src/templates/business/TemplateGalleryMedia.tsx`)는 `item.onClick`이 있을 때 `cursor-pointer hover:bg-surface-raised` 스타일을 적용하도록 이미 구현되어 있으나, `automationGalleryItems`의 각 항목에 `onClick`을 지정하지 않아 정적인 카드로만 렌더링됨.
3. **[execution-issue]** 카드 커버 색상에 상태 의미 토큰(`success`/`warning`/`danger`/`info`)을 장식 목적으로 혼용함 — `CardMediaCover`(`brand`/`success`/`warning`/`danger`/`info`)는 상태 표시용 토큰인데, 이번 스토리는 카테고리 구분용 장식색으로 임의 배정해 브랜드 톤 일관성이 흔들림. `src/components/data`, `src/templates/business`를 확인한 결과 카테고리 전용 장식 색상 토큰이 별도로 없는 것은 맞지만, 기존 상태 토큰을 오용한 것이므로 이번 실행에서 브랜드 색(`brand-subtle` 계열 등) 조합으로 대체 가능해 execution-issue로 분류함.
