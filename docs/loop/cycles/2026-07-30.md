## 오늘의 스코프

오늘은 `docs/loop/backlog.md`에 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목이 없어(B001~B011 모두 "완료" 상태), 정책 7항에 따라 `docs/loop/benchmark-suite.md`의 고정 목록을 cursor 순서대로 소비합니다. 현재 cursor 값은 4이므로 0-based 인덱스 4에 해당하는 **BM05 — Notion 템플릿 갤러리** (https://www.notion.so/templates, 패턴: 카드 그리드/갤러리)를 오늘의 벤치마크로 선택했습니다.

Notion 템플릿 갤러리는 카테고리 필터와 함께 다수의 템플릿을 카드 그리드로 진열하는 외부 서비스형(`service`) 갤러리 패턴입니다. 재현·평가 단계에서 기존 `src/templates/`의 카드 그리드/갤러리 계열(예: TemplateGallery, Figma·Trello·Asana 계열 재현 결과)과 대조해, 목적이 겹치지 않는 구조적 갭(design-system-gap)만 승격 후보로 삼습니다.

선택 처리 후 benchmark-suite의 cursor 값을 (4 + 1) % 10 = **5**로 갱신했습니다(다음 사이클은 BM06 Zendesk Help Center).

## 재현 전 중복 대조 결과

`src/templates/business/TemplateGallery.tsx`(카테고리 사이드바 + 아이콘 카드)와 `src/templates/business/TemplateGalleryMedia.tsx`(카테고리 사이드바 + 추천 섹션 + 이미지 카드)가 이미 "ERP/OMS/WMS/PRM/그룹웨어 카테고리로 나뉜 템플릿 카드 그리드"라는 Notion 벤치마크의 핵심 구조를 커버하고 있어, 정책 2항(중복 금지)과 PATTERNS.md 3절("80% 이상 겹치면 새로 만들지 않는다")에 따라 세 번째 전체 페이지 템플릿을 신규 추가하지 않았습니다.

Notion 템플릿 갤러리와 대조해 구조적으로 비어 있던 지점만 갭으로 승격했습니다.

- **상단 가로 카테고리 필터 바**: 기존 두 템플릿은 모두 좌측 세로 내비게이션만 지원. Notion은 좌측 내비 없이 상단 가로 pill 형태로 카테고리를 노출.
- **카드별 제공자/사용 현황 표기**: 기존 카드는 배지·설명까지만 있고, "누가 만들었는지 + 얼마나 쓰이는지"를 보여주는 하단 메타 정보가 없었음.

## 처리 내역

`TemplateGalleryMedia`에 `categoryLayout?: 'sidebar' | 'top'`(기본값 `sidebar`로 기존 화면 시각적 결과 불변)과 카드 아이템의 `author`/`authorAvatarSrc`/`usageLabel` optional prop을 추가해 위 두 갭을 채웠습니다. 신규 템플릿 파일을 만드는 대신 기존 컴포넌트를 확장하는 방식을 택했습니다(정책 9항, 컨시스턴시 유지).

부수적으로 `TemplateGalleryMedia`가 `src/templates/index.ts`에 export되어 있지 않고 스토리도 연결되어 있지 않던(이전 사이클에서 미완결로 남은) 상태를 함께 정리했습니다: index.ts export 추가, `src/stories/templates/Business.stories.tsx`에 `TemplateStore`(Template Store) 스토리를 추가해 `categoryLayout="top"` + author/usageLabel 조합을 한글 예시 데이터로 시연했습니다.

design-system-gap 승격 항목: 카드 그리드 갤러리의 "상단 가로 필터 + 카드 제공자/사용량 메타" 조합. execution-issue(시스템 변경 없이 기록만): 없음.

### 갭 목록 (3점 이하 항목)

- **componentFidelity — execution-issue**: `src/components/data/CardMedia.tsx`를 확인한 결과 `image` prop으로 실제 썸네일 이미지를 표시하는 기능이 이미 구현되어 있음(`image && <img ... />`). 그런데 `src/stories/templates/Business.stories.tsx`의 `templateStoreItems` 데이터가 `image`를 전혀 채우지 않고 `cover` 색상만 지정해, 이번 구현이 이미 있는 이미지 썸네일 기능을 활용하지 못함. 컴포넌트/토큰 추가 없이 스토리 데이터에 `image` 값만 채우면 해결 가능.
- **interaction — execution-issue**: `src/templates/business/TemplateGalleryMedia.tsx`의 `TemplateCard`는 `item.onClick`이 있을 때만 `cursor-pointer hover:bg-surface-raised` 클래스를 적용하도록 이미 작성되어 있음(컴포넌트 자체는 호버 상태를 지원). 그러나 `Business.stories.tsx`의 `templateStoreItems`가 각 항목에 `onClick`을 전달하지 않아 카드가 클릭 불가능한 정적 요소로 렌더링됨. `src/components`, `src/templates`를 확인한 결과 호버 시 나타나는 "템플릿 사용하기"류 오버레이 CTA 패턴은 별도로 존재하지 않으나, 기본 호버/클릭 피드백은 컴포넌트에 이미 있어 우선 execution-issue로 분류함.

### 비고

- 시스템 업그레이드(신규 컴포넌트/토큰 추가)는 필요하지 않다고 판단했습니다. 두 갭 모두 기존 `TemplateGalleryMedia`/`CardMedia`가 이미 지원하는 기능을 스토리 예시 데이터에서 활용하지 않은 execution-issue이므로, 다음 사이클에서 `templateStoreItems`에 `image`와 `onClick`을 채우는 실행 개선으로 처리 권장.
- design-system-gap으로 승격할 항목은 없습니다(호버 오버레이 CTA 패턴은 참고용으로만 기록, 점수 미달의 직접 원인은 아님).
