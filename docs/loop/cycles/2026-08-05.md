## 오늘의 스코프

오늘은 `docs/loop/backlog.md`에 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목이 없어(B001~B013 모두 "완료" 상태), 정책 7항에 따라 `docs/loop/benchmark-suite.md`의 고정 목록을 cursor 순서대로 소비합니다. 현재 cursor 값은 7이므로 0-based 인덱스 7에 해당하는 **BM08 — Atlassian Statuspage 소개** (https://www.atlassian.com/software/statuspage, 패턴: 모니터링/상태)를 오늘의 벤치마크로 선택했습니다.

Atlassian Statuspage 소개 페이지는 서비스 상태 모니터링 제품을 소개하는 외부 마케팅형(`service`) 페이지로, 히어로 섹션·기능 소개 블록·상태 컴포넌트(가동/장애/점검 상태 표시)·CTA 등을 조합한 레이아웃입니다. 재현·평가 단계에서 기존 `src/templates/`의 상태/모니터링 및 기능 소개 계열 패턴과 대조해, 정책 2항(중복 금지)·PATTERNS.md 기준에 따라 목적이 겹치는 신규 템플릿은 추가하지 않고, 구조적으로 비어 있는 갭(design-system-gap)만 승격 후보로 삼습니다. 특히 정책 3항에 따라 이 페이지가 외부 서비스형(`service`) 축인 점과 사내 기간계 축의 실제 운영 상태 대시보드 요구를 구분해, 두 축을 뒤섞지 않도록 유의합니다.

선택 처리 후 benchmark-suite의 cursor 값을 (7 + 1) % 10 = **8**로 갱신했습니다(다음 사이클은 BM09 Asana 템플릿 갤러리).

## 완성도 평가

- **벤치마크**: BM08 — Atlassian Statuspage 소개 (https://www.atlassian.com/software/statuspage)
- **자사 구현**: `Templates/Business` / export명 `SystemStatus` (story id `templates-business--system-status`, 컴포넌트 `src/templates/business/SystemStatusBoard.tsx`)
- **벤치마크 스크린샷**: 캡처 실패 — 세션 아웃바운드 프록시 정책이 `www.atlassian.com`에 대한 CONNECT를 403으로 차단함(`curl -sS "$HTTPS_PROXY/__agentproxy/status"`의 `recentRelayFailures`에 `connect_rejected`로 기록된 org policy denial — 재시도/우회하지 않고 보고 처리). 따라서 아래 평가는 Statuspage 제품의 공개적으로 잘 알려진 화면 구성(전체 상태 배너, 구독/Subscribe CTA, 컴포넌트별 90일 가동 이력 바, 장애 이력)에 대한 일반 지식 기반 비교이며, 실제 픽셀 대조는 아님을 명시합니다.
- **자사 스크린샷**: `docs/loop/screenshots/2026-08-05-ours.png`

### 갭 목록

1. **90일 가동 이력 바(`UptimeHistoryStrip`) 렌더링 버그** — 컴포넌트 자체는 `src/components/data/UptimeHistoryStrip.tsx`에 이미 존재하고, 오늘 스토리(`Business.stories.tsx`의 `makeUptimeHistory()`)에서도 각 시스템에 `history` 데이터를 실제로 채워 호출했으나, 화면·스크린샷에 막대가 전혀 보이지 않음. 원인을 재현 확인한 결과 `UptimeHistoryStrip` 단독 스토리(`data-uptimehistorystrip--default`)에서도 동일하게 막대가 보이지 않았고, `src/components/overlay/Tooltip.tsx`가 자식을 `inline-flex` span으로 감싸면서 그 안의 `flex-1` 클래스가 `UptimeHistoryStrip`의 `flex gap-0.5` 컨테이너가 아니라 `Tooltip`의 `inline-flex` 래퍼를 기준으로 계산되어 폭이 0으로 접히는 것이 원인으로 확인됨. 컴포넌트/패턴 자체는 이미 존재하므로 design-system-gap이 아니며, 기존 컴포넌트의 결함을 이번 스토리 구현 시 인지·회피하지 못한 것이므로 execution-issue로 분류함(근본 수정은 `UptimeHistoryStrip`/`Tooltip` 자체의 버그 픽스가 필요).
   - 분류: `execution-issue`
2. **구독/CTA 버튼 미사용** — `src/components/foundation/Button.tsx`가 이미 존재하고 `SystemStatusBoardProps.actions`도 정의되어 있으나, 이번 스토리 구현에서 `actions`를 채우지 않아 구독/알림 신청 같은 CTA가 화면에 전혀 나타나지 않음.
   - 분류: `execution-issue`

### 제안

- `UptimeHistoryStrip`/`Tooltip`의 flex 레이아웃 버그를 수정(`Tooltip`이 감싸는 `inline-flex` wrapper에 `flex-1`을 전달하거나, `UptimeHistoryStrip`에서 `Tooltip` 대신 `title` 속성을 쓰는 대안 검토).
- `SystemStatusBoard` 스토리에 기존 `Button`을 활용해 `actions`(구독 CTA)를 채우는 실행 개선(별도 컴포넌트 신설 불필요).
