## 오늘의 스코프

오늘 사이클 시작 시점 백로그에는 status가 "대기"인 항목이 없었습니다(B001~B007 모두 완료). 따라서 정책 5·6항 및 태스크 5단계, 그리고 직전 2026-07-11·2026-07-13 사이클의 선례에 따라 기존 `src/components`, `src/templates` 커버리지 갭을 분석해 신규 pm-proposed 항목 3개를 백로그에 먼저 등록한 뒤 일일 스코프 상한(1~3개) 내에서 모두 진행합니다.

기존 `src/templates/business/`는 17종(목록·상세·폼·대시보드·모니터링·승인·설정·리포트·마스터디테일·마법사폼·문서카탈로그·칸반·타임라인·일정·인박스·파일탐색기·통합검색)을 커버하고 있어, 이와 목적이 겹치지 않는 내부 업무 패턴 3개를 선정했습니다.

선정한 항목:

- **B008 — Roles & Permissions Matrix 템플릿 (역할·권한 관리 매트릭스)**: 역할별 리소스·기능 권한을 격자로 부여·관리하는 접근제어 레이아웃이 부재. ERP(Enterprise Resource Planning)·OMS(Order Management System)·WMS(Warehouse Management System) 사용자 권한 관리, PRM(Partner Management System) 파트너 등급별 접근 제어에 재활용도가 가장 높다고 판단해 최우선 선정. SettingsPage(일반 환경설정 폼)와 목적이 명확히 구분됩니다.
- **B009 — Help Desk / Ticket Detail 템플릿 (문의·티켓 상세 대화 스레드)**: 단일 문의 건을 상태·담당자·SLA와 함께 시간순 대화 스레드로 처리하는 헬프데스크 상세 레이아웃이 부재. PRM 파트너 문의, 사내 IT 헬프데스크, 그룹웨어·팀즈(Microsoft Teams) 연동 요청 처리에 재활용도가 높음. InboxCenter(다건 알림 목록)·ActivityTimeline(감사 이력)과 달리 양방향 대화 처리 + 상태 전환이 목적이라 중복이 없습니다.
- **B010 — Version / Change Compare 템플릿 (버전·변경 비교 뷰)**: 두 버전·레코드를 좌우로 나란히 놓고 변경 항목을 강조 표시하는 비교 레이아웃이 부재. 계약서 개정 대조, ERP 설정 변경 승인, 발주·사양 변경 전후 비교 등 내부통제·승인 흐름에서 재활용 가치가 높음. DetailView(단건 상세)·ApprovalView(단건 승인)와 달리 두 상태 대조가 목적이라 중복이 없습니다.

공통 근거:

- 세 항목 모두 기존 `src/templates/business/` 17종과 목적이 겹치지 않아 정책 2항(DRY)에 위배되지 않습니다.
- 세 항목 모두 기존 디자인 토큰과 컴포넌트(Table, Checkbox, Switch, Card, Avatar, Tag, StatusBadge, Divider, Textarea, Button, Grid, Stack 등)만으로 재구현 가능하여 정책 4항(신규 의존성 금지)을 준수합니다.
- 세 항목 모두 소비자용 트렌드가 아닌 내부 업무 시스템 패턴이라 정책 3항(적합성)에 부합합니다.

## 품질 비교

> 참고용 소견입니다 — 최종 채택 여부를 판단하는 근거가 아니며, 레이아웃/구조 비교를 위한 참고 자료입니다.

**중요 — 벤치마크 스크린샷 캡처 한계 고지**: 세 벤치마크 URL 모두 세션의 아웃바운드 프록시 정책에 의해 실제 사이트 콘텐츠를 캡처할 수 없었습니다.
- `docs.github.com`, `www.zendesk.com`: `curl`/Playwright 요청이 `CONNECT tunnel failed, response 403`으로 즉시 차단됨(정책 차단, 재시도 불가).
- `github.com`: CONNECT 자체는 통과하나 세션에 연결된 GitHub API 게이트웨이가 요청을 가로채 `"This GitHub API path is not available: sessions are bound to their configured repositories"` JSON 오류를 반환하여 실제 Compare 페이지에는 도달할 수 없음.

이에 따라 `*-benchmark.png` 파일은 실제 벤치마크 사이트의 스크린샷이 아니라, 위 차단 사실과 근거(curl 응답 코드)를 기록한 안내 이미지입니다. 실제 벤치마크 화면과의 시각적 비교는 이번 사이클에서 수행하지 못했으며, 아래 소견은 벤치마크 URL의 공개된 구조적 특징(정책 등록 시점에 확인한 내용)에 대한 기억 기반 참고 설명임을 밝힙니다. 확인 가능한 링크는 위에 표기된 URL이며, 직접 접속하여 대조하시기 바랍니다.
