## 오늘의 스코프

`docs/loop/backlog.md`에 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목이 없어(B001~B013 모두 "완료" 상태), 정책 7항에 따라 `docs/loop/benchmark-suite.md`의 고정 목록을 cursor 순서대로 소비합니다.

현재 cursor 값은 1이고 표에 10개 행(BM01~BM10)이 있으므로, 0-based 인덱스 1번째 행인 **BM02 — GitHub Issues 리스트(공개 저장소)**(https://github.com/facebook/react/issues, 패턴: 리스트/필터)를 오늘의 벤치마크로 선택했습니다. 직전 사이클(2026-08-11)에서 BM01을 소비하고 cursor가 1로 진행된 이어받기에 해당합니다.

선택 처리 후 benchmark-suite의 cursor 값을 (1 + 1) % 10 = **2**로 갱신했습니다(다음 사이클은 BM03 GitHub 검색 결과).

GitHub Issues 리스트는 상단 필터/검색 바 + 라벨·상태·담당자 필터 + 이슈 행 목록(제목, 라벨 태그, 담당자 아바타, 상태 아이콘, 코멘트 수 등)으로 구성된 리스트/필터 패턴입니다. 개발·업무 대상의 다건 항목 조회·필터·처리 성격이 강해 정책 3항에 따라 기간계(business) 축을 기준으로 재현·평가합니다. 재현 시 기존 `src/templates/`의 리스트/필터 계열(예: ListSearchTable 등)과 대조해 정책 2항(중복 금지)에 따라 목적이 겹치는 신규 템플릿은 추가하지 않고, 구조적으로 비어 있는 갭(design-system-gap)만 승격 후보로 삼습니다.

## 완성도 평가

**구현 스토리**: title `Templates/Business`, export `IssueList` (story id `templates-business--issue-list`, name "Issue List Board", 컴포넌트: `src/templates/business/IssueListBoard.tsx`)

**벤치마크**: GitHub Issues 리스트 (공개 저장소) — https://github.com/facebook/react/issues

**스크린샷**:
- 자사: `docs/loop/screenshots/2026-08-13-ours.png`
- 벤치마크: 촬영 실패 — 세션 egress 프록시가 `github.com` 웹 페이지 접근을 정책상 차단(403, "GitHub access to this repository is not enabled for this session")하여 Playwright로 벤치마크 URL을 캡처할 수 없었습니다. `add_repo`로 `facebook/react`를 확인했으나 이는 git clone/API 경로만 열어주고, 웹 UI(`https://github.com/.../issues`) HTML 페이지 접근은 별도로 차단되어 있었습니다(raw.githubusercontent.com은 200으로 정상 접근됨). 따라서 이번 평가는 GitHub Issues 리스트 UI에 대한 기존 지식(라벨 필터 사이드바, 상단 정렬/필터 바, 체크박스 일괄 선택, 행별 상태 아이콘·라벨 배지·담당자 아바타·코멘트 수, 하단 페이지네이션)을 기준으로 진행했습니다. 이 한계는 다음 사이클에서 프록시 정책 변경 시 재검증이 필요합니다.

**갭 목록 (3점 이하 항목 원인, 분류 포함)**

1. **라벨 색상 구분 미사용** — `src/components/foundation/Badge.tsx`에 `success/warning/danger/info` color variant가 이미 존재하는데, `IssueListBoard.tsx`는 색상 없는 `src/components/data/Tag.tsx`만 사용해 라벨(OMS/버그/ERP/긴급 등)이 모두 동일한 회색 톤으로 표시됨. → **execution-issue**
2. **행 체크박스(일괄 선택) 없음** — `src/components/form/Checkbox.tsx`가 이미 존재하는데 `IssueListBoard`에서 사용하지 않음. → **execution-issue**
3. **페이지네이션 없음** — `src/components/navigation/Pagination.tsx`가 이미 존재하는데 목록 하단에 배치되지 않음(현재는 4~6건뿐이라 스토리 데이터상 드러나지 않지만 구조적으로 컴포넌트가 누락). → **execution-issue**
4. **정렬/필터 드롭다운 없음** — `filters` slot은 있으나 스토리에서 단순 `Select`("시스템 전체") 1개만 채워져 있고, `src/components/overlay/DropdownMenu.tsx` 등을 활용한 정렬(최신순/댓글순 등) 컨트롤이 없음. → **execution-issue**
5. **좌측 필터 사이드바 없음** — `src/components/navigation/Sidebar.tsx`가 존재하지만 `IssueListBoard`는 단일 컬럼 레이아웃만 사용해 라벨/마일스톤/담당자별 필터 패널을 구성하지 않음. → **execution-issue**
6. **담당자 아바타 이미지 미사용** — `Avatar` 컴포넌트가 `src` prop을 지원하지만 스토리 데이터가 `initials`만 전달해 이미지 아바타를 확인할 수 없음(컴포넌트 자체는 지원하므로 데이터 구성 문제). → **execution-issue**

전 항목이 `src/components`, `src/templates`를 직접 확인한 결과 상응 컴포넌트/토큰이 이미 존재함을 확인했으므로 **design-system-gap은 없음**. 이번 사이클은 구조적 컴포넌트 추가보다 기존 컴포넌트 활용도를 높이는 실행 개선이 필요한 사례입니다.
