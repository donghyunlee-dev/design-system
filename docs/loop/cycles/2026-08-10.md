## 오늘의 스코프

백로그(`docs/loop/backlog.md`)에 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목이 없어(B001~B013 모두 "완료" 상태), 정책 7항에 따라 `docs/loop/benchmark-suite.md`의 고정 목록을 cursor 순서대로 소비합니다.

현재 cursor 값은 0이었고 표에 10개 행(BM01~BM10)이 있으므로, 0-based 인덱스 0번째 행인 **BM01 — Stripe Docs 홈**(https://docs.stripe.com, 패턴: 문서/네비게이션)을 오늘의 벤치마크로 선택했습니다. 직전 사이클(2026-08-07)에서 BM10을 소비하고 cursor가 0으로 순환한 뒤 첫 회귀 순회에 해당합니다(policy 7항, 회귀 테스트).

선택 처리 후 benchmark-suite의 cursor 값을 (0 + 1) % 10 = **1**로 갱신했습니다(다음 사이클은 BM02 GitHub Issues 리스트).

Stripe Docs 홈은 좌측 네비게이션(섹션·카테고리 트리) + 본문 문서 + 상단 검색으로 구성된 외부 서비스형(`service`) 문서/네비게이션 패턴입니다. 정책 3항에 따라 이 페이지가 일반 웹사이트(`service`) 축에 해당함을 유의하여 사내 기간계 축과 뒤섞지 않고, 재현·평가 단계에서 기존 `src/templates/`의 문서/네비게이션 계열(예: DocsHub, DocumentCatalog 등)과 대조해 정책 2항(중복 금지) 기준으로 목적이 겹치는 신규 템플릿은 추가하지 않으며, 구조적으로 비어 있는 갭(design-system-gap)만 승격 후보로 삼습니다.

## 완성도 평가

- 벤치마크: Stripe Docs 홈 (https://docs.stripe.com)
- 자사 구현: `Templates/Business` — export `DocsHome`(스토리 표시명 "Docs Hub", story id `templates-business--docs-home`), 내부적으로 `src/templates/business/DocsHub.tsx` 사용
- 참고: 조직 아웃바운드 정책상 `docs.stripe.com`으로의 CONNECT가 프록시에서 403으로 차단되어(egress 정책 거부) 벤치마크 실측 스크린샷은 촬영하지 못했습니다. 아래 점수는 자사 스크린샷과 Stripe Docs 홈에 대한 일반적으로 알려진 구조(좌측 카테고리 내비게이션, 상단 검색/커맨드팔레트, 카드형 가이드 그리드)에 대한 평가자의 기존 지식을 근거로 매긴 것이며, 픽셀 단위 대조는 아닙니다.

### 갭 목록

1. **interaction — execution-issue**: `src/components/overlay/CommandPalette.tsx`에 커맨드 팔레트(검색 오버레이 + 키보드 트리거) 컴포넌트가 이미 존재함에도, 이번 `DocsHome` 구현은 상단 검색을 일반 텍스트 `Input`으로만 배치해 자동완성, 단축키 힌트, 결과 미리보기 같은 인터랙션을 전혀 제공하지 않습니다. 컴포넌트가 이미 있으므로 design-system-gap이 아니라 이번 구현에서 활용하지 못한 execution-issue로 분류합니다.
2. **componentFidelity — execution-issue**: 카드(가이드 카드) 및 검색 입력에 아이콘·hover/focus 시각 강조가 부족합니다. `src/components`에 아이콘 배지, Input 등 기본 요소는 존재하나 이번 스토리에서 강조 스타일을 적극적으로 조합하지 않아 Stripe 카드 대비 완성도가 낮게 느껴집니다. 이 역시 컴포넌트 부재가 아니라 활용 부족이므로 execution-issue입니다.
