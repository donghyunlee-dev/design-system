## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했습니다. 정책 7항에 따라 사람이 등록했거나 평가에서 발견된 갭 항목은 벤치마크 순회보다 우선 소비해야 하기 때문입니다. 검토 결과 B001~B015가 모두 "완료" 상태이며 "대기" 항목이 하나도 없어, benchmark-suite 고정 목록을 cursor 순서대로 소비합니다.

`docs/loop/benchmark-suite.md`의 frontmatter cursor 값은 1이고 표는 10개 행(BM01~BM10)이므로, 0-based 인덱스 1에 해당하는 **BM02 — GitHub Issues 리스트 (공개 저장소)**(https://github.com/facebook/react/issues, 패턴: 리스트/필터)를 오늘의 벤치마크로 선택합니다. 직전 사이클(2026-09-03, BM01)에서 회귀 순회가 재개되었고 cursor가 1로 갱신되었으므로, 이번 사이클은 그 다음 항목인 BM02를 소비합니다. 처리 후 cursor는 (1+1) % 10 = 2로 갱신했습니다.

BM02는 오픈소스 저장소의 이슈 트래커 목록 화면으로, 상단 필터·검색 바 + 라벨/상태 필터 + 이슈 행(제목·라벨·작성자·코멘트 수·상태 아이콘) 리스트 + 페이지네이션으로 구성된 "리스트/필터" 패턴에 해당합니다. 축 판단상 GitHub의 이슈 트래커는 외부 개발자를 대상으로 하지만 구조적으로는 기간계(business/admin)의 목록·필터 조회 화면(ListSearchTable, GlobalSearchResults, 각종 관리 목록 등)과 재활용 축이 겹치므로, 재현·평가 시 다음 정책 가드레일을 유의합니다.

- 정책 3항(축 분리): 이 패턴이 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단하고, 그 축(리스트/필터는 기간계 조회 화면 축) 안에서 이미 있는 패턴과 겹치지 않는 갭만 채택합니다. 두 축을 뒤섞은 패턴은 채택하지 않습니다.
- 정책 2항(중복 금지, DRY): 신규 작업에 앞서 `src/components/`·`src/templates/`(특히 기존 ListSearchTable, GlobalSearchResults, Table/Tag/StatusBadge/Filter 계열 자산)를 대조해 리스트/필터 조회와 목적이 겹치는 자산이 이미 있는지 확인한 뒤에만 추가 범위를 확정합니다. 이미 채운 갭은 반복 채택하지 않습니다.
- 정책 8항(갭 승격 기준): 발견된 부족 항목을 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap으로 판정된 경우에만 컴포넌트/토큰을 추가합니다. execution-issue는 시스템을 변경하지 않고 리포트에만 기록합니다.
- 정책 9항(일관성 유지): 업그레이드가 필요하더라도 전체 컨셉·스타일을 유지하는 범위 내 추가만 허용하며, 기존 시맨틱 토큰 체계 밖의 색상값 하드코딩이나 새로운 스타일링 체계 도입은 금지합니다.
- 정책 5항(병합 게이트): 모든 변경은 `develop` 대상 PR로만 제출하며, `main`/`develop` 직접 push는 금지합니다.

benchmark-suite 항목을 선택했으므로 `docs/loop/backlog.md`의 status는 이번 사이클에서 변경하지 않으며, benchmark-suite의 cursor만 1에서 2로 갱신했습니다.

### 갭 목록

1. **componentFidelity 저하 원인** — `src/stories/templates/Business.stories.tsx`의 `prmInquiries` 목데이터가 `assignee.initials`에 `'박서준'`, `'김민준'` 같은 3자 전체 이름을 그대로 넣었습니다(2560~2618행). `src/components/foundation/Avatar.tsx`는 24px(`w-6 h-6`) 원 안에 `initials` 문자열을 그대로 출력하며 `whitespace-nowrap`이나 글자 수 제한이 없어, 3자 텍스트가 원 안에서 줄바꿈되어 스크린샷에서 담당자 아바타가 깨진 텍스트("삭사중", "심단주"처럼 보이는 잘림)로 표시되고 옆의 댓글 수 아이콘과도 겹칩니다. `Avatar` 컴포넌트 자체와 이니셜 표시 패턴은 이미 존재하므로, 부재한 것은 컴포넌트가 아니라 (a) 스토리의 잘못된 목데이터(이니셜 대신 전체 이름 사용)와 (b) `Avatar`가 긴 입력에 방어적이지 않은 점입니다.
   - 분류: `execution-issue`
2. **interaction 저하 원인** — `src/templates/business/SavedViewIssueBoard.tsx`의 이슈 행에는 체크박스가 없고 `bulkActions`/`selectedIds` 같은 일괄 선택 개념이 아예 props에 정의되어 있지 않습니다. 다만 `src/components/form/Checkbox.tsx`에 체크박스 컴포넌트 자체는 이미 존재하며, 같은 파일의 다른 스토리(List Search Table 등)에서 `selectedIds`/`bulkActions` 패턴이 실제로 사용되고 있는 것도 확인했습니다. 즉 부재한 것은 컴포넌트가 아니라 이번 템플릿 구현에서의 활용입니다.
   - 분류: `execution-issue`
