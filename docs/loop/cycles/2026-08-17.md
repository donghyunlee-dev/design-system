## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했으나, B001~B013이 모두 "완료" 상태여서 대기 중인 사람 등록 항목이 없습니다. 따라서 정책 7항에 따라 `docs/loop/benchmark-suite.md`의 고정 목록을 cursor 순서대로 소비합니다.

현재 cursor 값은 1이고 표에 10개 행(BM01~BM10)이 있으므로, 0-based 인덱스 1번째 행인 **BM02 — GitHub Issues 리스트(공개 저장소)**(https://github.com/facebook/react/issues, 패턴: 리스트/필터)를 오늘의 벤치마크로 선택했습니다. 직전 사이클(2026-08-11)이 BM01을 소비하고 cursor를 1로 갱신했으므로, 이번 사이클은 그 다음 순번인 BM02로 이어집니다.

선택 처리 후 cursor 값을 (1 + 1) % 10 = **2**로 갱신했습니다(다음 사이클은 BM03 GitHub 검색 결과).

정책 3항에 따라 이 페이지가 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단하고, 해당 축에서 기존 컴포넌트/템플릿과 겹치지 않는 구조적 갭(design-system-gap)만 채택합니다. GitHub Issues 리스트는 상단 필터·검색 바 + 라벨/상태/담당자 기반 필터 + 이슈 행 리스트(제목·번호·라벨·작성자·코멘트 수)로 구성된 리스트/필터 패턴이며, 이슈·작업 항목을 목록으로 조회·필터링하는 내부 업무 도구 성격이 강해 기간계(business) 축을 기준으로 재현·평가합니다. 재현 시 기존 리스트/필터 계열(ListSearchTable 등)과 대조해 정책 2항(중복 금지)에 따라 목적이 겹치는 신규 템플릿은 추가하지 않고, 발견된 부족 항목은 정책 8항 기준으로 design-system-gap과 execution-issue를 구분해 처리합니다.

### 갭 목록

1. **라벨 색상 구분 미흡 (execution-issue)**: `src/components/foundation/Badge.tsx`에 `variant: 'default' | 'success' | 'warning' | 'danger' | 'info'` 색상 배지가 이미 존재하는데도, `SystemIssueTracker.tsx`는 라벨 렌더링에 `Tag`(중립 단일 톤, 색상 variant 없음)만 사용해 "긴급/버그/문의/개선" 같은 라벨의 의미적 구분이 사라짐. 컴포넌트는 이미 있으므로 design-system-gap이 아니라 execution-issue로 분류하며, 시스템 변경 없이 리포트에만 기록함(정책 8항).
2. **인터랙션 상태 미검증 (execution-issue)**: 스토리 자체에는 선택 체크박스, 일괄 처리 액션, 정렬/필터 드롭다운 로직이 이미 구현되어 있으나(`selectedIds`, `bulkActions`, `DropdownMenu`, `Select` 등 기존 컴포넌트 재사용), 오늘 캡처한 기본 스토리 상태에서는 선택 0건 상태만 보여 hover/선택/드롭다운 오픈 등 실제 상태 전환이 화면에 드러나지 않음. 컴포넌트/패턴이 없는 것이 아니라 이번 스크린샷 캡처 범위의 한계이므로 execution-issue로 분류.

design-system-gap으로 분류된 항목은 없음 — `src/components`(Badge, Tag, DropdownMenu, Checkbox, Select 등)와 `src/templates/business`(ListSearchTable, IssueListBoard 등)를 확인한 결과 GitHub Issues 리스트 재현에 필요한 컴포넌트/패턴은 이미 모두 존재함. 따라서 이번 사이클은 시스템 업그레이드(Upgrade 단계) 없이 리포트 기록으로 종료.
