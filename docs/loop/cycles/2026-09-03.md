## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했습니다. 정책 7항에 따라 사람이 등록했거나 평가에서 발견된 갭 항목은 벤치마크 순회보다 우선 소비해야 하기 때문입니다. 검토 결과 B001~B015가 모두 "완료" 상태이며 "대기" 항목이 하나도 없어, benchmark-suite 고정 목록을 cursor 순서대로 소비합니다.

`docs/loop/benchmark-suite.md`의 frontmatter cursor 값은 0이고 표는 10개 행(BM01~BM10)이므로, 0-based 인덱스 0에 해당하는 **BM01 — Stripe Docs 홈**(https://docs.stripe.com, 패턴: 문서/네비게이션)을 오늘의 벤치마크로 선택합니다. 직전 사이클(2026-09-01, BM10)에서 목록 끝에 도달해 cursor가 0으로 순환했으므로, 이번 사이클부터 BM01을 기점으로 회귀 순회가 다시 시작됩니다(정책 7항). 처리 후 cursor는 (0+1) % 10 = 1로 갱신했습니다.

BM01은 개발자 문서 포털의 홈으로, 좌측 사이드바 네비게이션 + 중앙 본문 + 검색 진입점 + 제품별 카드 구성을 가진 "문서/네비게이션" 패턴에 해당합니다. 축 판단상 외부 개발자를 대상으로 하지만 구조적으로는 기간계(business/admin)의 문서/매뉴얼 화면(DocsHub, DocumentCatalog, HelpArticleView 등)과 재활용 축이 겹치므로, 재현·평가 시 다음 정책 가드레일을 유의합니다.

- 정책 3항(축 분리): 이 패턴이 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단하고, 그 축 안에서 이미 있는 패턴과 겹치지 않는 갭만 채택합니다. 두 축을 뒤섞은 패턴은 채택하지 않습니다.
- 정책 2항(중복 금지, DRY): 신규 작업에 앞서 `src/components/`·`src/templates/`(특히 기존 DocsHub/DocumentCatalog/HelpArticleView 등 문서·네비게이션 자산과 B011 Command Palette 관련 자산)를 대조해 목적이 겹치는 자산이 이미 있는지 확인한 뒤에만 추가 범위를 확정합니다. BM01은 회귀 순회 첫 항목이므로, 과거 Stripe Docs 관련 사이클(2026-07-22 DocsHub 등)에서 이미 채운 갭은 반복 채택하지 않습니다.
- 정책 8항(갭 승격 기준): 발견된 부족 항목을 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap으로 판정된 경우에만 컴포넌트/토큰을 추가합니다. execution-issue는 시스템을 변경하지 않고 리포트에만 기록합니다.
- 정책 9항(일관성 유지): 업그레이드가 필요하더라도 전체 컨셉·스타일을 유지하는 범위 내 추가만 허용하며, 기존 시맨틱 토큰 체계 밖의 색상값 하드코딩이나 새로운 스타일링 체계 도입은 금지합니다.
- 정책 5항(병합 게이트): 모든 변경은 `develop` 대상 PR로만 제출하며, `main`/`develop` 직접 push는 금지합니다.

### 갭 목록

1. **카드 여백: `Card`의 `lg` 패딩 옵션을 활용하지 않음 — execution-issue**
   - `src/components/data/Card.tsx`(19번째 줄)를 보면 `padding` prop이 `'sm' | 'md' | 'lg'`를 이미 지원합니다(`lg`→`p-6`). 그런데 `DocsHub.tsx`의 카드 렌더링부(158~172번째 줄)는 `padding` prop을 전달하지 않아 기본값 `md`(`p-4`)로 고정되어, Stripe 홈처럼 여유 있는 카드 여백을 낼 수 있는 기존 옵션을 쓰지 못했습니다. 컴포넌트 자체는 이미 존재하므로 시스템 보강 없이 템플릿/스토리 사용 방식만 바꾸면 해결됩니다.
2. **인터랙션 상태 확인 부족 — execution-issue**
   - 정적 스크린샷만으로는 카드·바로가기 버튼의 hover(`hover:bg-surface-raised`, `hover:bg-surface-subtle`) 등 이미 코드에 구현된 상태 스타일을 확인하지 못했습니다. 컴포넌트에 상태 스타일 자체는 이미 존재하므로(`DocsHub.tsx` 162·188번째 줄) 시스템 갭이 아니라, 이번 평가 절차(정적 캡처 1장)의 한계로 기록합니다.

design-system-gap으로 새로 확정된 항목은 없습니다. `src/components/foundation`, `src/templates/business`를 확인한 결과 아이콘(HubIcon), 카드(Card), 태그(Tag), 네비게이션(Breadcrumb) 등 이번 화면에 필요한 컴포넌트/토큰이 모두 이미 존재하며, 낮은 점수(typography 3, interaction 3)의 원인은 모두 기존 옵션(Card `padding="lg"`)을 쓰지 않았거나 정적 캡처의 한계였습니다. 따라서 이번 사이클은 시스템 변경 없이 execution-issue 2건만 기록합니다.
