## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했습니다. 정책 7항에 따라 사람이 등록했거나 평가에서 발견된 갭 항목은 벤치마크 순회보다 우선 소비해야 하기 때문입니다. 검토 결과 B001~B015가 모두 "완료" 상태이며 "대기" 항목이 하나도 없어, benchmark-suite 고정 목록을 cursor 순서대로 소비합니다.

`docs/loop/benchmark-suite.md`의 frontmatter cursor 값은 9이고 표는 10개 행(BM01~BM10)이므로, 0-based 인덱스 9에 해당하는 **BM10 — Basecamp 기능 소개**(https://basecamp.com/features, 패턴: 기능 소개/섹션 레이아웃)를 오늘의 벤치마크로 선택합니다. 이 항목은 목록의 마지막 행이므로 처리 후 cursor는 (9+1) % 10 = 0으로 갱신했습니다. 다음 사이클부터는 BM01(Stripe Docs 홈)부터 회귀 순회가 다시 시작됩니다(정책 7항).

BM10은 외부 서비스(`service`) 축의 제품 기능 소개(마케팅) 페이지로, 여러 기능을 섹션 단위로 세로로 이어 붙여 각 기능의 설명·스크린샷·부제를 교차 배치하는 "기능 소개/섹션 레이아웃" 패턴에 해당합니다. 재현·평가 단계에서 유의할 정책 가드레일은 다음과 같습니다.

- 정책 3항(축 분리): 이 패턴이 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단합니다. Basecamp 기능 소개는 외부 마케팅성 랜딩에 가까운 service 축이므로, 그 축 안에서 이미 있는 패턴과 겹치지 않는 갭만 채택하고, 두 축을 뒤섞은 패턴(예: 사내 도구에 마케팅 랜딩의 화려한 모션·비비드 톤을 그대로 이식)은 채택하지 않습니다. 직전 BM09(Asana) 사이클에서 "비비드/마케팅 톤 색상·일러스트 토큰 부재"를 정책상 의도된 공백으로 판정해 배제한 선례가 있으므로, 동일 성격의 갭은 반복 채택하지 않습니다.
- 정책 2항(중복 금지, DRY): 신규 작업에 앞서 `src/components/`·`src/templates/`(특히 `service` 축 템플릿과 섹션형 레이아웃 컴포넌트)를 대조해 기능 소개/섹션 레이아웃과 목적이 겹치는 자산이 이미 있는지 확인한 뒤에만 추가 범위를 확정합니다. BM10과 유사한 섹션형 마케팅 레이아웃 벤치마크(BM08 Statuspage, BM10 Basecamp)가 있으므로 그와 겹치지 않는 신규 구조적 갭만 채택합니다.
- 정책 8항(갭 승격 기준): 발견된 부족 항목을 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap으로 판정된 경우에만 컴포넌트/토큰을 추가합니다. execution-issue는 시스템을 변경하지 않고 리포트에만 기록합니다.
- 정책 9항(일관성 유지): 업그레이드가 필요하더라도 전체 컨셉·스타일을 유지하는 범위 내 추가만 허용하며, 기존 시맨틱 토큰 체계 밖의 색상값 하드코딩이나 새로운 스타일링 체계 도입은 금지합니다.
- 정책 5항(병합 게이트): 모든 변경은 `develop` 대상 PR로만 제출하며, `main`/`develop` 직접 push는 금지합니다.

benchmark-suite 항목을 선택했으므로 `docs/loop/backlog.md`의 status는 이번 사이클에서 변경하지 않으며, benchmark-suite의 cursor만 9에서 0으로 갱신했습니다.

## 완성도 평가

**벤치마크**: BM10 — Basecamp 기능 소개 (https://basecamp.com/features)
**구현 스토리**: title "Templates/Service/Landing", export "FeatureShowcaseStory" (id: `templates-service-landing--feature-showcase-story`)

> 참고: 벤치마크 URL(`basecamp.com`)이 조직 egress 정책(403 Forbidden)에 의해 이 세션에서 차단되어 벤치마크 스크린샷은 촬영하지 못했습니다. 아래 점수는 자사 스크린샷과 Basecamp 기능 소개 페이지에 대한 일반적 지식(섹션 교차 배치, 실제 스크린샷/일러스트 활용, 비비드 브랜드 컬러 사용)을 기준으로 평가했습니다.

### 점수 (1~5)

| 항목 | 점수 | 비고 |
|---|---|---|
| layout (레이아웃/구조) | 4 | 히어로 → 퀵점프 → 좌/우 교차 2단 섹션 → 클로징 CTA 구조는 벤치마크의 섹션 나열 패턴과 유사하게 재현됨 |
| componentFidelity (컴포넌트 충실도) | 3 | 4개 기능 섹션 모두 실제 화면 미리보기 대신 빈 placeholder("화면 미리보기" 텍스트 박스)로만 채워짐 |
| typography (타이포그래피/여백) | 4 | 타입 스케일·여백(spacing 토큰)은 일관되게 적용됨 |
| interaction (인터랙션/상태) | 3 | 정적 스크린샷으로는 nav/퀵점프 링크의 hover 등 실제 인터랙션 상태를 확인할 수 없고, 스토리에도 별도 상태 데모가 없음 |
| brandTone (브랜드 톤 일관성) | 2 | 모든 배지(eyebrow)가 `Badge` 기본(gray) variant만 사용되어 페이지 전체가 단조로운 흑백톤이며, CTA 버튼 외에는 브랜드 컬러가 거의 드러나지 않음 |

### 갭 목록

1. **componentFidelity 저하 원인** — `src/components/data/MediaCard.tsx`가 이미 존재하지만(이미지/미디어 카드 컴포넌트), `FeatureShowcaseStory`(`src/stories/templates/Landing.stories.tsx`)에서 `FeatureShowcaseSection.media` prop을 전혀 채우지 않아 4개 섹션 전부 기본 placeholder("화면 미리보기")로 렌더링됨. `src/components`, `src/templates`를 확인한 결과 상응하는 컴포넌트가 이미 있으므로
   - 분류: **execution-issue** (컴포넌트는 있으나 이번 구현에서 활용하지 못함)

2. **interaction 저하 원인** — `Button`(`src/components/foundation/Button.tsx`)과 nav 링크에는 이미 hover/포커스 스타일이 정의돼 있으나(`hover:text-brand`, `hover:text-foreground` 등), 정적 스크린샷 평가와 스토리 자체에 상태 변화를 보여주는 별도 데모가 없어 인터랙션 품질을 확인할 길이 없음. 컴포넌트 자체의 상태 처리는 이미 구현되어 있음
   - 분류: **execution-issue** (토큰/컴포넌트 상태 스타일은 있으나 스토리에서 노출·검증하지 않음)

3. **brandTone 저하 원인** — `Badge`(`src/components/foundation/Badge.tsx`)는 `default/success/warning/danger/info` 5가지 색상 variant를 이미 지원하지만, `FeatureShowcase` 템플릿은 모든 eyebrow 배지에 `variant` 미지정(기본 gray)만 사용해 섹션마다 톤을 구분하지 못하고 페이지 전체가 단조로운 흑백 인상을 줌. 색상 토큰과 variant는 이미 존재함
   - 분류: **execution-issue** (색상 variant는 있으나 브랜드 톤 강조에 활용하지 못함)

   참고: 직전 BM09(Asana) 사이클에서 "비비드/마케팅 톤 색상·일러스트 토큰 부재"는 정책 3항(축 분리)에 따라 서비스 축에 의도적으로 배제된 공백으로 판정한 바 있어, 새로운 비비드 색상 토큰·일러스트 자산을 design-system-gap으로 추가하지 않음. 이번 갭은 어디까지나 기존 `Badge` variant를 실행 단계에서 활용하지 않은 문제로 한정함.

### 결론

이번 사이클에서 새로 확인된 항목은 모두 **execution-issue**로, `src/components`·`src/templates`에 상응 자산(MediaCard, Badge 색상 variant, 기존 hover 스타일)이 이미 존재함을 확인했습니다. 디자인 시스템 자체를 확장할 구조적 갭(design-system-gap)은 발견되지 않았으므로 컴포넌트/토큰 추가 작업은 진행하지 않습니다. 후속 조치로 `FeatureShowcaseStory`에서 `media`에 `MediaCard` 목업을 채우고 섹션별 `Badge`에 색상 variant를 지정하는 개선을 백로그에 등록하는 것을 권장합니다.
