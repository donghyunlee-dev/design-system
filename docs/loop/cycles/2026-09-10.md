## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했습니다. 정책 7항에 따라 사람이 등록했거나 평가에서 발견된 갭 항목은 벤치마크 순회보다 우선 소비해야 하기 때문입니다. 검토 결과 B001~B015가 모두 "완료" 상태이며 "대기" 항목이 하나도 없어, 이번 사이클은 `docs/loop/benchmark-suite.md` 고정 목록을 cursor 순서대로 소비합니다.

`docs/loop/benchmark-suite.md`의 frontmatter cursor 값은 2이고 표는 10개 행(BM01~BM10)이므로, 0-based 인덱스 2에 해당하는 **BM03 — GitHub 검색 결과**(https://github.com/search?q=react&type=repositories, 패턴: 검색 결과)를 오늘의 벤치마크로 선택합니다. 직전 사이클(2026-09-08)에서 BM02(cursor 1)를 소비하며 cursor를 2로 갱신했으므로 이번 사이클은 그 다음 항목을 이어서 처리합니다. 처리 후 cursor는 (2+1) % 10 = 3으로 갱신했습니다.

BM03은 검색어 입력 결과를 좌측 타입/언어 등 패싯 필터 + 상단 정렬·결과 수 요약 + 각 결과 행에 저장소명·설명·언어·스타/토픽 태그 등 메타를 담은 리스트로 구성된 "검색 결과" 패턴에 해당합니다. 구조적으로는 여러 조건으로 좁혀 조회하는 리스트/필터 계열이며, 기존 자산(ListSearchTable, Global Search Results(B007))과 재활용 축이 겹칠 가능성이 있으므로 재현·평가 시 다음 정책 가드레일을 유의합니다.

- 정책 3항(축 분리): 이 패턴이 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단하고, 그 축 안에서 이미 있는 패턴과 겹치지 않는 갭만 채택합니다. 두 축을 뒤섞은 패턴은 채택하지 않습니다.
- 정책 2항(중복 금지, DRY): 신규 작업에 앞서 `src/components/`·`src/templates/`(특히 기존 ListSearchTable, Global Search Results(B007), Table/Tag/StatusBadge/패싯 필터 관련 자산)를 대조해 검색 결과·패싯 필터와 목적이 겹치는 자산이 이미 있는지 확인한 뒤에만 추가 범위를 확정합니다. 목적이 겹치는 기존 패턴이 있으면 반복 채택하지 않습니다.
- 정책 8항(갭 승격 기준): 발견된 부족 항목을 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap으로 판정된 경우에만 컴포넌트/토큰을 추가합니다. execution-issue는 시스템을 변경하지 않고 리포트에만 기록합니다.

### 갭 목록

1. **검색어 키워드 하이라이트 부재** — [design-system-gap]
   - `src/components`, `src/templates` 전체를 확인했으나 결과 텍스트 내 검색어를 강조(`<mark>` 등)하는 컴포넌트/패턴이 존재하지 않습니다. (`highlight` 키워드로 검색 시 `DataTable.test.tsx` 외 매치 없음)
   - GitHub 검색 결과는 매칭된 키워드를 강조 표시해 스캔성을 높이는데, 이에 대응할 자산이 시스템에 아예 없어 이번 구현에서도 재현하지 못했습니다.

2. **결과 항목의 아바타/아이콘/색상 배지 미사용** — [execution-issue]
   - `Avatar`(`src/components/foundation/Avatar.tsx`), `Icon`(`src/components/foundation/Icon.tsx`), `ColorTag`(`src/components/data/ColorTag.tsx`)가 이미 존재하지만 `EntitySearchExplorer.tsx`의 결과 카드는 제목·설명·통계 텍스트·`Tag`만 사용하고 이들 컴포넌트를 활용하지 않았습니다.
   - 컴포넌트는 있으나 이번 스토리 구성(더미 데이터)에서 적용하지 않아 시각적 밀도가 낮아진 execution-issue로 분류합니다.

3. **패싯 필터가 체크박스가 아닌 단일 버튼 토글** — [execution-issue]
   - `Checkbox`(`src/components/form/Checkbox.tsx`)가 이미 존재하지만 `EntitySearchExplorer`의 좌측 패싯은 클릭 버튼(`active` 배경 강조)만 사용하고 있어, 다중 선택 상태임에도 체크박스 시각 언어를 쓰지 않았습니다.
   - GitHub 등 일반적인 패싯 UI의 체크박스 패턴을 이미 보유한 `Checkbox` 컴포넌트로 표현할 수 있었던 점에서 execution-issue로 분류합니다.

### 결론

design-system-gap은 "검색어 하이라이트" 1건뿐이며, 나머지 저점 원인은 모두 기존 컴포넌트(Avatar/Icon/ColorTag/Checkbox)를 활용하지 못한 execution-issue입니다. 정책 8항에 따라 시스템(컴포넌트/토큰) 변경은 design-system-gap 1건에 한해 백로그에 등록을 검토하고, execution-issue 2건은 시스템 변경 없이 본 리포트로만 기록합니다.
