## 오늘의 스코프

`docs/loop/backlog.md`에 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목이 없어(B001~B013 모두 "완료" 상태), 정책 7항에 따라 `docs/loop/benchmark-suite.md`의 고정 목록을 cursor 순서대로 소비합니다.

현재 cursor 값은 1이고 표에 10개 행(BM01~BM10)이 있으므로, 0-based 인덱스 1번째 행인 **BM02 — GitHub Issues 리스트(공개 저장소)**(https://github.com/facebook/react/issues, 패턴: 리스트/필터)를 오늘의 벤치마크로 선택했습니다. 직전 사이클(2026-08-11)에서 BM01을 소비하며 cursor를 1로 갱신한 순회의 다음 항목에 해당합니다.

선택 처리 후 benchmark-suite의 cursor 값을 (1 + 1) % 10 = **2**로 갱신했습니다(다음 사이클은 BM03 GitHub 검색 결과).

정책 3항에 따라 이 페이지가 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단합니다. GitHub Issues 리스트는 상단 필터/검색 바 + 좌측 라벨·마일스톤 필터 + 이슈 행 목록(상태 아이콘, 제목, 라벨, 담당자, 코멘트 수)으로 구성된 리스트/필터 패턴으로, 다수 항목을 상태·조건으로 걸러 처리하는 내부 업무 성격이 강해 기간계(business) 축을 기준으로 재현·평가합니다.

재현·평가 단계에서 기존 `src/templates/business/`의 리스트/필터 계열(ListSearchTable, GlobalSearchResults, NotificationInbox 등)과 대조해 정책 2항(중복 금지)에 따라 목적이 겹치는 신규 템플릿은 추가하지 않으며, 구조적으로 비어 있는 갭(design-system-gap)만 승격 후보로 삼습니다. execution-issue로 판정되는 항목은 시스템을 변경하지 않고 리포트에만 기록합니다(정책 8항).

## 완성도 평가

**벤치마크**: GitHub Issues 리스트 (공개 저장소) — https://github.com/facebook/react/issues (BM02)

**대상 스토리**: `Templates/Business` / `IssueList` (export) — Storybook id `templates-business--issue-list`, 표시명 "Issue List Board"

**스크린샷**
- 자사: `docs/loop/screenshots/2026-08-14-ours.png`
- 벤치마크: 캡처 실패 — 이 세션의 아웃바운드 네트워크 정책이 `github.com`에 대한 일반 웹 브라우징(HTTPS GET/CONNECT)을 차단하고 있어(curl/Playwright 모두 403과 함께 "GitHub access to this repository is not enabled for this session" 응답을 반환), git 프로토콜(clone/fetch)만 허용됩니다. 조직 정책 차단이므로 우회를 시도하지 않았고, 대신 GitHub Issues 리스트의 통상적인 UI 패턴(체크박스, 상태 아이콘, 라벨 pill, 담당자 아바타, 코멘트 수, 필터/정렬 드롭다운, 페이지네이션)에 대한 지식을 기준으로 비교했습니다. 관리자에게 보고가 필요한 사항입니다.

**점수 (1~5)**

| 항목 | 점수 | 비고 |
|---|---|---|
| layout (레이아웃/구조) | 4 | 브레드크럼 → 제목/CTA → 열림/닫힘 탭 → 검색·필터 바 → 체크박스 포함 이슈 행 목록 → 페이지네이션 순서로 GitHub Issues의 핵심 구조를 그대로 재현. 다만 GitHub은 좌측에 라벨/마일스톤 패싯 필터 패널을 두는 반면 본 구현은 상단 드롭다운(시스템/담당자/정렬) 3개로 단순화함 |
| componentFidelity (컴포넌트 충실도) | 4 | Badge/Tag(시스템·유형 라벨), Checkbox(전체선택·행선택), Avatar(담당자 이니셜), Pagination 등 기존 `src/components`를 그대로 재사용. GitHub은 프로필 이미지 아바타를 쓰지만 사내 시스템 맥락상 이니셜 아바타로 대체한 것은 합리적 |
| typography (타이포그래피/여백) | 4 | 제목 굵기·행간·라벨 pill 크기 등이 다른 business 템플릿과 일관되며 여백도 정돈되어 있음. GitHub 대비 행 간 정보 밀도(라벨 다중 표기, 마일스톤 아이콘 등)는 다소 낮음 |
| interaction (인터랙션/상태) | 4 | 컴포넌트 코드(`IssueListBoard.tsx`) 확인 결과 행 클릭(`onItemClick`, hover 시 `hover:bg-surface-raised`), 개별/전체 체크박스 선택, 선택 시 나타나는 벌크 액션 바(`{selectedIds.length}개 선택됨`)가 모두 구현되어 있음. 다만 정적 스크린샷 1장으로는 이 상태들이 시각적으로 검증되지 않음 |
| brandTone (브랜드 톤 일관성) | 5 | 레드 포인트 컬러의 CTA, 한국어 라벨링, 다른 business 템플릿과 동일한 카드/보더 스타일로 톤이 일관됨 |

**갭 목록**: 3점 이하 항목 없음 (모든 항목 4점 이상) → design-system-gap/execution-issue 승격 대상 없음.

참고(점수에는 반영하지 않은 관찰): GitHub처럼 좌측 라벨·마일스톤 패싯 필터가 필요한 벤치마크가 향후 나올 경우, `src/templates/business/FacetedSearchResults.tsx`가 이미 해당 패턴(패싯 사이드바)을 보유하고 있으므로 신규 컴포넌트 없이 조합 가능함 — design-system-gap이 아님.
