## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했습니다. 정책 7항에 따라 사람이 등록했거나 평가에서 발견된 갭 항목은 벤치마크 순회보다 우선 소비해야 하기 때문입니다. 검토 결과 B001~B015가 모두 "완료" 상태이며 "대기" 항목이 하나도 없어, benchmark-suite 고정 목록을 cursor 순서대로 소비합니다.

`docs/loop/benchmark-suite.md`의 frontmatter cursor 값은 3이고 표는 10개 행(BM01~BM10)이므로, 0-based 인덱스 3에 해당하는 **BM04 — Trello 템플릿 갤러리**(https://trello.com/templates/business, 패턴: 카드 그리드/템플릿)를 오늘의 벤치마크로 선택합니다. 직전 사이클(2026-09-09, BM03)에서 cursor를 3으로 갱신했으므로 이번 사이클은 그 다음 항목을 이어서 처리합니다(정책 7항 회귀 순회). 처리 후 cursor는 (3+1) % 10 = 4로 갱신했습니다.

BM04는 업무용 템플릿을 카테고리별로 모아 카드 그리드로 탐색하는 "카드 그리드/템플릿" 패턴에 해당합니다. 상단 히어로/검색 + 좌측 또는 상단 카테고리 필터 + 각 템플릿을 썸네일·제목·설명·작성자로 표현하는 카드 그리드 + 카드 호버/선택 인터랙션으로 구성됩니다. 구조적으로는 기존 템플릿 갤러리·카드 그리드 자산(DocumentCatalog, MediaCard, Notion/Figma 재현 시 다뤘던 카드 그리드 계열)과 재활용 축이 겹치므로, 재현·평가 시 다음 정책 가드레일을 유의합니다.

- 정책 3항(축 분리): 이 패턴이 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단하고, 그 축 안에서 이미 있는 패턴과 겹치지 않는 갭만 채택합니다. BM04는 외부 서비스의 템플릿 갤러리(마케팅·탐색성) 성격이 강하므로 service 축과 대조하되, 두 축을 뒤섞은 패턴은 채택하지 않습니다.
- 정책 2항(중복 금지, DRY): 신규 작업에 앞서 `src/components/`·`src/templates/`(특히 MediaCard, MediaCardHoverActions, DocumentCatalog, 기존 카드 그리드/갤러리 자산)를 대조해 목적이 겹치는 자산이 이미 있는지 확인한 뒤에만 추가 범위를 확정합니다. 목적이 겹치는 기존 패턴이 있으면 반복 채택하지 않습니다.
- 정책 8항(갭 승격 기준): 발견된 부족 항목을 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap으로 판정된 경우에만 컴포넌트/토큰을 추가합니다. execution-issue는 시스템을 변경하지 않고 리포트에만 기록합니다.
- 정책 9항(일관성 유지): 업그레이드가 필요하더라도 전체 컨셉·스타일을 유지하는 범위 내 추가만 허용하며, 기존 시맨틱 토큰 체계 밖의 색상값 하드코딩이나 새로운 스타일링 체계 도입은 금지합니다.
- 정책 5항(병합 게이트): 모든 변경은 `develop` 대상 PR로만 제출하며, `main`/`develop` 직접 push는 금지합니다.

benchmark-suite 항목을 선택했으므로 `docs/loop/backlog.md`의 status는 이번 사이클에서 변경하지 않으며, benchmark-suite의 cursor만 3에서 4로 갱신했습니다.

- 벤치마크: Trello 템플릿 갤러리 (https://trello.com/templates/business)
- 구현 스토리: title "Templates/Business", export "TemplateGalleryFilteredStory" (id: `templates-business--template-gallery-filtered-story`)
- 스크린샷: 자사 `docs/loop/screenshots/2026-09-11-ours.png` / 벤치마크 스크린샷 없음 — egress 프록시가 조직 정책으로 `trello.com` CONNECT를 거부(403)해 Playwright로 벤치마크 페이지에 접속하지 못했습니다(`curl $HTTPS_PROXY/__agentproxy/status`의 `recentRelayFailures`에 `trello.com:443 connect_rejected` 기록). 따라서 이번 평가는 자사 화면을 Trello 템플릿 갤러리에 대한 기존 지식(과거 사이클 기록, 일반적인 카드 그리드/템플릿 갤러리 패턴 지식)과 대조한 결과이며, 픽셀 단위 비교는 아닙니다.

### 갭 목록

1. **componentFidelity 저하 — 카드 썸네일 미활용** — classification: `execution-issue`
   - `src/components/data/MediaCard.tsx`를 확인한 결과 `image`(실제 썸네일 URL)와 `cover`(브랜드/success/warning/danger/info 단색 커버) prop이 이미 존재함. 그런데 `TemplateGalleryFiltered.tsx`의 `TemplateCard`는 `item.icon`을 `fallback`으로만 넘기고 `thumbnailSrc`/`cover`를 실제로 채운 데이터가 없어 모든 카드가 동일한 무채색 placeholder로 보임. 컴포넌트/토큰이 이미 있으므로 시스템 갭이 아니라 이번 구현에서 데이터·props를 다 쓰지 않은 실행 이슈로 분류함.
2. **interaction 저하 — 호버 액션 오버레이 미사용** — classification: `execution-issue`
   - `src/components/data/MediaCardHoverActions.tsx`를 확인한 결과 카드 위에 호버 시 반투명 오버레이로 액션 버튼을 노출하는 컴포지션 래퍼가 이미 존재함(주석에 "design-system-gap 대응"으로 이미 추가된 자산이라고 명시됨). `TemplateGalleryFiltered`의 `TemplateCard`는 이 래퍼를 쓰지 않고 액션 버튼을 카드 하단에 항상 노출시켜, Trello 특유의 호버 인터랙션을 재현하지 못함. 상응 컴포넌트가 이미 있으므로 시스템 갭이 아닌 실행 이슈로 분류함.

정책 8항에 따라 위 두 항목은 모두 `execution-issue`로 판정되어 이번 사이클에서는 컴포넌트/토큰을 추가하지 않았습니다(Upgrade 단계 스킵). `src/components/data`, `src/templates/business`를 확인한 결과 목적이 겹치는 자산(MediaCard, MediaCardHoverActions, Tag, Checkbox, Grid 등)이 이미 모두 존재해 design-system-gap으로 승격할 항목은 없었습니다.
