## 오늘의 스코프

오늘 사이클 시작 시점 백로그에는 status가 "대기"인 항목이 없었습니다(B001~B007 모두 완료). 따라서 정책 5항 및 태스크 5단계, 그리고 직전 2026-07-11·2026-07-13 사이클의 선례에 따라 기존 `src/components`, `src/templates/business` 커버리지 갭을 분석해 신규 pm-proposed 항목 3개를 백로그에 먼저 등록한 뒤 일일 스코프 상한(1~3개) 내에서 모두 진행합니다.

선정한 항목:

- **B008 — Data Import Wizard 템플릿 (파일 일괄 업로드·매핑·검증)**: CSV·Excel 파일을 업로드해 컬럼을 대상 필드에 매핑하고 검증 결과(오류·경고 행)를 미리 본 뒤 일괄 반영하는 데이터 임포트 레이아웃이 부재. OMS(Order Management System) 주문 일괄 등록, WMS(Warehouse Management System) 재고 동기화, PRM(Partner Management System) 파트너 일괄 등록 등 내부 업무 시스템에서 가장 빈번한 대량 데이터 취입 패턴이라 최우선 선정. WizardForm(단건 다단계 폼)·FormRegister(단건 등록)와 달리 파일 기반 대량 취입·검증이 목적이라 중복이 없습니다.
- **B009 — Permission / Role Matrix 템플릿 (RBAC 권한 관리)**: 역할(Role)과 권한(Permission)을 행·열 매트릭스로 배치해 체크박스로 접근 권한을 일괄 관리하는 레이아웃이 부재. 다수 내부 시스템(ERP·OMS·WMS)의 사용자 접근 통제(RBAC, Role-Based Access Control) 관리 화면에 재활용도가 높아 선정. SettingsPage(키-값 환경설정)와 달리 역할×권한 교차 매트릭스 편집이 목적이라 중복이 없습니다.
- **B010 — Comparison / Diff View 템플릿 (버전·항목 비교 뷰)**: 두 레코드·버전을 좌우 병렬로 놓고 변경 필드를 강조 표시하는 비교 레이아웃이 부재. 계약·사양 개정 이력, ERP 설정 변경 전후, 단가 변경 승인 비교 등 감사·내부통제 관점에서 재활용 가치가 높아 선정. MasterDetail(목록+단일 상세)·ActivityTimeline(시간순 이력)과 달리 두 대상의 필드 단위 좌우 대조가 목적이라 중복이 없습니다.

공통 근거:

- 세 항목 모두 기존 `src/templates/business/`(목록·상세·폼·대시보드·모니터링·승인·설정·리포트·마스터디테일·마법사폼·문서카탈로그·칸반·타임라인·일정·인박스·파일탐색기·통합검색) 17종과 목적이 겹치지 않아 정책 2항(DRY)에 위배되지 않습니다.
- 세 항목 모두 기존 디자인 토큰과 컴포넌트(Stepper, FileUpload, Table, Checkbox, Card, Tag, StatusBadge, Grid, Divider, Stack 등)만으로 재구현 가능하여 정책 4항(신규 의존성 금지)을 준수합니다.
- 세 항목 모두 소비자용 마케팅 트렌드가 아닌 내부 업무 시스템 패턴이라 정책 3항(적합성)에 부합합니다.

## PM 방향 제안 로그

신규 제안 3건(B008, B009, B010)을 backlog.md에 source: pm-proposed로 등록한 뒤 오늘 스코프에 포함했습니다.

- 근거: 커버리지 갭 분석 결과, 내부 업무 시스템에서 빈번한 3개 패턴(파일 일괄 임포트 마법사 / RBAC 권한 매트릭스 / 버전·항목 비교 뷰)이 기존 17종 business 템플릿에 존재하지 않음을 확인했습니다. 즉흥 진행을 피하기 위해 백로그에 먼저 등록한 후 진행중 상태로 전환했습니다.
- 우선순위: B008 > B009 > B010 (내부 시스템 재활용 빈도 기준). 3건 모두 일일 상한(3개) 이내이며 신규 의존성 없이 기존 컴포넌트 조합으로 구현 가능합니다.
- 각 항목별 품질 비교 벤치마크(참고용, 코드 복사 아님 — 레이아웃/구조만 참고, 모두 로그인 없이 공개 열람 가능 — 정책 7항 준수):
  - B008: PatternFly Wizard (https://www.patternfly.org/components/wizard) — Red Hat 오픈 디자인 시스템의 공개 컴포넌트 문서. 다단계(업로드→매핑→검증→완료) 마법사 흐름과 리뷰 단계 구조 참고에 적합.
  - B009: GitHub Docs — Repository roles (https://docs.github.com/en/organizations/managing-user-access-to-your-organizations-repositories/managing-repository-roles/repository-roles-for-an-organization) — 로그인 없이 열람 가능한 공개 문서로, 역할×권한 매트릭스 표의 대표적 표현.
  - B010: Diffchecker (https://www.diffchecker.com) — 로그인 없이 좌우 병렬 비교 + 변경 강조 UI를 공개 제공하는 대표적 비교/디프 화면.

## 품질 비교

Storybook(`npm run dev`, 포트 6006)을 기동해 각 항목의 Ours 스크린샷은 정상적으로 확보했습니다. 다만 벤치마크 사이트 3건(patternfly.org, docs.github.com, www.diffchecker.com) 모두 세션의 아웃바운드 egress 정책에 의해 프록시 단계에서 403(정책 거부)로 차단되어 있어, Playwright는 물론 WebFetch로도 접근이 불가능했습니다(`curl -sS $HTTPS_PROXY/__agentproxy/status`의 `recentRelayFailures`에 세 호스트 모두 `connect_rejected` 기록). 이에 따라 벤치마크 스크린샷은 이번 사이클에서 확보하지 못했으며, 아래 소견은 Ours 스크린샷과 이전에 문서화된 벤치마크 사이트에 대한 서술적 기억을 바탕으로 한 참고용 소견입니다(최종 판단 아님). 벤치마크 사이트 접근이 허용되는 환경에서 재캡처가 필요합니다.

- 벤치마크: PatternFly — Wizard (https://www.patternfly.org/components/wizard)
- Ours 스크린샷: `docs/loop/screenshots/2026-07-14-B008-ours.png`
- 벤치마크 스크린샷: 미확보 (조직 egress 정책 403으로 접근 차단, 위 사유 참고)
