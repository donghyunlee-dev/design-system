## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했으나, B001~B013이 모두 "완료" 상태여서 대기 중인 사람 등록 항목이 없습니다. 따라서 정책 7항에 따라 `docs/loop/benchmark-suite.md`의 고정 목록을 cursor 순서대로 소비합니다.

현재 cursor 값은 3이고 표에 10개 행(BM01~BM10)이 있으므로, 0-based 인덱스 3번째 행인 **BM04 — Trello 템플릿 갤러리**(https://trello.com/templates/business, 패턴: 카드 그리드/템플릿)를 오늘의 벤치마크로 선택했습니다. 직전 사이클(2026-08-18)이 BM03을 소비하고 cursor를 3으로 갱신한 순회의 다음 항목에 해당합니다.

선택 처리 후 benchmark-suite의 cursor 값을 (3 + 1) % 10 = **4**로 갱신했습니다(다음 사이클은 BM05 Notion 템플릿 갤러리).

정책 3항에 따라 이 페이지가 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단합니다. Trello 템플릿 갤러리는 상단 카테고리 네비게이션 + 카테고리 헤더 + 템플릿 카드 그리드(썸네일·제목·작성자·설명)로 구성된 카드 그리드/템플릿 갤러리 패턴으로, 외부 사용자가 템플릿을 둘러보고 선택하도록 유도하는 서비스/카탈로그 성격이 강합니다. 다만 사내 기간계에서도 업무 템플릿·양식 갤러리(예: 승인 양식·보고서 템플릿 선택)로 재활용 여지가 있어, 재현·평가 단계에서 두 축 중 어느 쪽으로 재현할지 정책 3항 기준으로 확정합니다.

재현·평가 단계에서 기존 `src/components/`(MediaCard 등 카드 계열)와 `src/templates/`의 카드 그리드/갤러리 계열(Notion·Figma·Asana 재현 사이클에서 다뤄진 갤러리 템플릿 포함)을 대조해, 정책 2항(중복 금지)에 따라 목적이 겹치는 신규 템플릿은 추가하지 않습니다. 발견된 부족 항목은 정책 8항 기준으로 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap만 시스템 업그레이드 후보로 삼고 execution-issue는 리포트에만 기록합니다.

## 완성도 평가

### 벤치마크 정보
- 벤치마크: Trello 템플릿 갤러리 (https://trello.com/templates/business)
- 재현 스토리: `Templates/Business` — export `TemplateGalleryDepartments` (story id: `templates-business--template-gallery-departments`, 표시명: "Template Gallery (Sidebar Nav)")
- **중요한 제약**: 사내 아웃바운드 프록시 정책상 `trello.com`으로의 HTTPS CONNECT가 403(정책 차단)으로 거부되어, 이번 사이클에서는 벤치마크 실제 페이지의 스크린샷을 확보하지 못했습니다. `/root/.ccr/README.md` 지침에 따라 조직 정책 차단(403)은 재시도하거나 우회하지 않았습니다. 따라서 아래 평가는 벤치마크 이미지와의 직접적인 픽셀/레이아웃 대조가 아니라, 학습된 일반 지식상의 Trello 템플릿 갤러리 패턴(상단 카테고리 탭, 실제 보드 썸네일 이미지가 들어간 카드, 클릭 가능한 카드, 밝고 다채로운 브랜드 톤)을 기준으로 자사 구현 스크린샷만 단독 검토한 결과입니다. 벤치마크 스크린샷은 저장하지 못했으며 `benchmarkScreenshotPath`는 빈 문자열로 보고합니다.

### 갭 목록

1. **[execution-issue]** 실제 템플릿 미리보기 이미지 미사용: `TemplateGalleryMediaItem.image` prop이 이미 존재함에도(`src/templates/business/TemplateGalleryMedia.tsx` 22행) 이번 스토리 데이터는 `image`를 전혀 지정하지 않고 `cover` 단색 토큰만 사용했습니다. `src/components/data/CardMedia.tsx`, `src/components/data/MediaCard.tsx` 모두 `coverSrc`/`image`로 실제 썸네일을 렌더링할 수 있으므로 컴포넌트 자체의 부재가 아니라 이번 구현에서 활용하지 않은 것입니다.
2. **[execution-issue]** 카드 클릭 인터랙션 미구현: `TemplateCard`(`TemplateGalleryMedia.tsx` 61~91행)는 `item.onClick`이 있을 때 hover 스타일과 클릭 가능 커서를 적용하도록 이미 만들어져 있으나, `departmentGalleryItems`(스토리 파일 1831~1839행)의 모든 항목이 `onClick`을 지정하지 않아 정적 카드로만 렌더링됩니다. 컴포넌트 API는 존재하므로 design-system-gap이 아닙니다.
3. **[execution-issue]** 카드 제목 타이포그래피 강조 약함: 카드 제목이 `text-sm font-semibold`로만 지정되어(`TemplateGalleryMedia.tsx` 72행) 그리드에서 시각적 임팩트가 약함. `Card`/`MediaCard` 컴포넌트 자체에는 제목 크기를 조절할 여지가 있어 토큰 부재가 아니라 이번 스토리에서 기본값을 그대로 사용한 결과입니다.
4. `src/components`, `src/templates/business` 확인 결과 카드형 템플릿 갤러리에 필요한 컴포넌트(카테고리 사이드바/탭, 검색 인풋, 배지, 아바타, 그리드, 미디어 카드)가 모두 이미 존재하여, 이번 사이클에서 design-system-gap으로 분류할 항목은 발견되지 않았습니다.
