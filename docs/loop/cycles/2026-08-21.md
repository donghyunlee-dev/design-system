## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했으나, B001~B013이 모두 "완료" 상태여서 대기 중인 사람 등록 항목이 없습니다. 따라서 정책 7항에 따라 `docs/loop/benchmark-suite.md`의 고정 목록을 cursor 순서대로 소비합니다.

현재 cursor 값은 5이고 표에 10개 행(BM01~BM10)이 있으므로, 0-based 인덱스 5번째 행인 **BM06 — Zendesk Help Center**(https://support.zendesk.com/hc/en-us, 패턴: 문서/FAQ)를 오늘의 벤치마크로 선택했습니다. 직전 사이클(2026-08-20)이 BM05를 소비하고 cursor를 5로 갱신한 순회의 다음 항목에 해당합니다.

선택 처리 후 benchmark-suite의 cursor 값을 (5 + 1) % 10 = **6**으로 갱신했습니다(다음 사이클은 BM07 Figma Community 홈).

정책 3항에 따라 이 페이지가 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단합니다. Zendesk Help Center는 상단 검색 히어로 + 카테고리 카드/목록 + 인기 아티클/FAQ 링크로 구성된 도움말 센터(지식베이스) 패턴으로, 외부 사용자가 문서를 검색·탐색하도록 유도하는 서비스/카탈로그 성격과, 사내 매뉴얼·헬프데스크·FAQ로 재활용 가능한 기간계 성격을 함께 가집니다. 재현·평가 단계에서 두 축 중 어느 쪽으로 재현할지 정책 3항 기준으로 확정합니다.

재현·평가 단계에서 기존 `src/components/`(검색 Input, Card, List, Breadcrumb, Accordion 등)와 `src/templates/`의 문서/네비게이션 계열(Stripe DocsHub, DocumentCatalog, GlobalSearch 등 과거 사이클 산출물 포함)을 대조해, 정책 2항(중복 금지)에 따라 목적이 겹치는 신규 템플릿은 추가하지 않습니다. 발견된 부족 항목은 정책 8항 기준으로 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap만 시스템 업그레이드 후보로 삼고 execution-issue는 리포트에만 기록합니다.

## 완성도 평가

**벤치마크**: Zendesk Help Center (https://support.zendesk.com/hc/en-us)
**오늘 구현한 스토리**: `Templates/Business` / `HelpCategoryArticlesList` (Storybook id: `templates-business--help-category-articles-list`)

- 자사 스크린샷: `docs/loop/screenshots/2026-08-21-ours.png`
- 벤치마크 스크린샷: 캡처 실패 — 조직 egress 정책이 `support.zendesk.com:443`으로의 CONNECT를 403으로 차단(`gateway answered 403 to CONNECT (policy denial or upstream failure)`). 프록시 상태 엔드포인트(`$HTTPS_PROXY/__agentproxy/status`)의 `recentRelayFailures`에 기록되어 있으며, 정책상 재시도/우회하지 않고 그대로 보고함. 평가는 기억 기반의 Zendesk Help Center 일반 패턴(상단 지속 검색바, 카테고리별 문서 목록, 문서 행 아이콘/클릭 어포던스)과 자사 화면을 대조해 수행함.

### 점수 (1~5)

| 항목 | 점수 | 비고 |
|---|---|---|
| layout | 4 | 브레드크럼 → 제목/설명 → 섹션별 문서 리스트 → 우측 인기 문서 사이드바 구조가 Zendesk 카테고리 페이지 구조와 유사함 |
| componentFidelity | 3 | 문서 목록/카드/브레드크럼 컴포넌트는 잘 재현했으나, 같은 도움말 템플릿군(`HelpCenter.tsx`)에 이미 있는 검색 Input을 이 카테고리 페이지에는 재사용하지 않음 |
| typography | 4 | 시스템 타이포 토큰(`text-2xl font-bold`, `text-sm text-muted` 등)과 여백이 일관되게 적용됨 |
| interaction | 3 | 문서 행에 `hover:bg-surface-subtle`와 chevron 아이콘으로 클릭 가능 신호는 있으나, 키보드 포커스 상태(`focus-visible`)가 정의되어 있지 않아 마우스 hover 외의 인터랙션 신호가 부족함 |
| brandTone | 4 | 중립 그레이스케일 배경, 카드/보더 스타일이 시스템 톤과 Zendesk의 차분한 헬프센터 톤에 부합 |

### 갭 목록

1. **[execution-issue]** 카테고리 문서 목록 페이지(`HelpCategoryArticles`)에 검색바가 없음. `src/components/form/Input.tsx`는 이미 존재하고, 같은 템플릿군인 `src/templates/business/HelpCenter.tsx`(도움말 홈)에서 검색 Input을 실제로 사용 중임을 확인했음에도 이번 구현에서는 재사용하지 않았음. Zendesk는 카테고리 페이지에서도 상단 검색을 유지함.
2. **[execution-issue]** 문서 행(`<a>`)과 인기 문서 사이드바 링크에 키보드 포커스 상태(`focus-visible` 등)가 전혀 정의되어 있지 않아 hover 없이 키보드로 탐색 시 어떤 항목이 선택되어 있는지 알 수 없음. `src/components/form/Input.tsx`(`focus:outline-none focus:ring-2 focus:ring-brand focus:border-brand`) 등 폼 컴포넌트에는 이미 포커스 링 컨벤션이 존재하므로, 이번 구현에서 해당 패턴을 재사용하지 않은 실행 이슈로 분류함. (※ 문서 행의 클릭 가능 신호(chevron)는 `ChevronRightIcon`을 통해 이미 적용되어 있어 별도 갭이 아님 — 최초 초안의 해당 항목은 오기였으므로 정정함.)
