## 오늘의 스코프

`docs/loop/backlog.md`에서 status가 "대기"이면서 source가 `human-added` 또는 `eval-found`인 항목을 먼저 확인했습니다. 정책 7항에 따라 사람이 등록했거나 평가에서 발견된 갭 항목은 벤치마크 순회보다 우선 소비해야 하기 때문입니다. 검토 결과 B001~B015가 모두 "완료" 상태이며 "대기" 항목이 하나도 없어, benchmark-suite 고정 목록을 cursor 순서대로 소비합니다.

`docs/loop/benchmark-suite.md`의 frontmatter cursor 값은 1이고 표는 10개 행(BM01~BM10)이므로, 0-based 인덱스 1에 해당하는 **BM02 — GitHub Issues 리스트 (공개 저장소)**(https://github.com/facebook/react/issues, 패턴: 리스트/필터)를 오늘의 벤치마크로 선택합니다. 직전 사이클(2026-09-03, BM01)에 이어 회귀 순회가 정상 진행 중입니다(정책 7항). 처리 후 cursor는 (1+1) % 10 = 2로 갱신했습니다.

BM02는 공개 저장소의 이슈 목록 화면으로, 상단 필터·검색 바 + 상태 탭(Open/Closed) + 좌측 라벨/담당자/마일스톤 등 다중 필터 + 행 단위 리스트(제목·라벨·번호·작성자·코멘트 수) + 정렬·페이지네이션 구조를 가진 "리스트/필터" 패턴에 해당합니다. 축 판단상 외부 개발자를 대상으로 하는 서비스이지만, 구조적으로는 기간계(business/admin)의 목록·검색 테이블 화면(ListSearchTable, GlobalSearchResults 등)과 재활용 축이 겹치므로, 재현·평가 시 다음 정책 가드레일을 유의합니다.

- 정책 3항(축 분리): 이 패턴이 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단하고, 그 축 안에서 이미 있는 패턴과 겹치지 않는 갭만 채택합니다. 이슈 목록은 데이터 조회·필터 중심이므로 기간계(business) 축의 리스트/필터 자산과 대조합니다. 두 축을 뒤섞은 패턴은 채택하지 않습니다.
- 정책 2항(중복 금지, DRY): 신규 작업에 앞서 `src/components/`·`src/templates/`(특히 기존 ListSearchTable, GlobalSearchResults, Table/Tag/StatusBadge/Pagination 등 리스트·필터 자산)를 대조해 목적이 겹치는 자산이 이미 있는지 확인한 뒤에만 추가 범위를 확정합니다.
- 정책 8항(갭 승격 기준): 발견된 부족 항목을 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap으로 판정된 경우에만 컴포넌트/토큰을 추가합니다. execution-issue는 시스템을 변경하지 않고 리포트에만 기록합니다.
- 정책 9항(일관성 유지): 업그레이드가 필요하더라도 전체 컨셉·스타일을 유지하는 범위 내 추가만 허용하며, 기존 시맨틱 토큰 체계 밖의 색상값 하드코딩이나 새로운 스타일링 체계 도입은 금지합니다.
- 정책 5항(병합 게이트): 모든 변경은 `develop` 대상 PR로만 제출하며, `main`/`develop` 직접 push는 금지합니다.

benchmark-suite 항목을 선택했으므로 `docs/loop/backlog.md`의 status는 이번 사이클에서 변경하지 않으며, benchmark-suite의 cursor만 1에서 2로 갱신했습니다.

## 완성도 평가

- 벤치마크: BM02 — GitHub Issues 리스트 (공개 저장소), https://github.com/facebook/react/issues
- 평가 대상 스토리: `Templates/Business` / `Issue List Board` (story id `templates-business--issue-list`, export `IssueList`, 컴포넌트 `src/templates/business/IssueListBoard.tsx`)
- 자사 스크린샷: `docs/loop/screenshots/2026-09-07-ours.png`
- 벤치마크 스크린샷: 캡처 불가. Playwright로 `https://github.com/facebook/react/issues` 접속 시 세션의 아웃바운드 프록시가 GitHub 호스트 요청을 가로채 `"GitHub access to this repository is not enabled for this session"` JSON 응답을 반환했습니다(`curl -sS "$HTTPS_PROXY/__agentproxy/status"` 확인 결과 `recentRelayFailures`는 비어 있어 일반 네트워크 장애가 아니라 GitHub 도메인에 대한 세션 정책 차단으로 판단). `add_repo`는 git 프로토콜 읽기 접근만 열어주며 브라우저 웹 접근에는 적용되지 않았습니다. 2026-07-21 사이클의 선례(정책 차단은 재시도하지 않고 사실만 기록)를 따라 재시도하지 않았고, 실패한 결과물(`docs/loop/screenshots/2026-09-07-benchmark.png`)은 삭제했습니다. 따라서 아래 점수는 GitHub Issues 목록 화면에 대한 사전 지식(Open/Closed 탭, 좌측 라벨·담당자·마일스톤 다중 패싯 필터, 행 단위 리스트: 제목·라벨·번호·작성자·코멘트 수·담당자 아바타, 정렬·페이지네이션)에 근거한 참고용 평가이며, 접근 가능한 환경에서 재검증이 필요합니다.

### 갭 목록

- **[execution-issue]** 좌측 다중 패싯 필터 패널 미사용: `src/templates/business/FacetedSearchResults.tsx`에 라벨/담당자 등 다중 패싯 필터 컴포넌트가 이미 존재하는데도 `IssueListBoard`는 이를 쓰지 않고 상단 드롭다운 3개(시스템/담당자/정렬)로 필터링을 단순화했습니다. 컴포넌트가 없는 것이 아니라 이번 구현에서 활용하지 않은 경우이므로 design-system-gap이 아닌 execution-issue로 분류합니다. 컴포넌트/토큰 추가 없이 리포트에만 기록합니다(정책 8항).
