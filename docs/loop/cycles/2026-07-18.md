## 오늘의 스코프

오늘 사이클 시작 시점 백로그에는 status가 "대기"인 항목이 없었습니다(B001~B007 모두 완료). 따라서 정책 5항(병합 게이트·자동 성장) 및 태스크 5단계, 그리고 직전 2026-07-11·2026-07-13 사이클의 선례에 따라 기존 `src/components`, `src/templates` 커버리지 갭을 분석해 신규 pm-proposed 항목 3개를 backlog.md에 먼저 등록한 뒤 일일 스코프 상한(1~3개) 내에서 모두 진행합니다.

선정한 항목:

- **B008 — Data Import / Column Mapping 템플릿 (대량 데이터 적재)**: CSV·Excel 업로드 → 원본 컬럼을 시스템 필드에 매핑 → 검증 결과 미리보기 → 적재로 이어지는 대량 데이터 임포트 레이아웃이 부재. ERP(Enterprise Resource Planning) 마스터 데이터, WMS(Warehouse Management System) 재고 일괄 등록, OMS(Order Management System) 주문 일괄 업로드 등 내부 업무 시스템 재활용도가 가장 높다고 판단해 최우선 선정. 기존 WizardForm(범용 다단계 입력 폼)과 달리 "컬럼 매핑 + 검증 미리보기 그리드"가 핵심이라 목적이 구분됩니다.
- **B009 — Permission / Role Matrix 템플릿 (접근권한 관리)**: 역할(Role) × 리소스/기능을 체크박스 격자로 교차 편집하는 RBAC 레이아웃이 부재. ERP·OMS·WMS·PRM(Partner Management System) 등 다수 시스템에서 역할별 권한 매트릭스가 반복적으로 필요합니다. SettingsPage(범용 키-값 설정 토글)와 달리 "역할×권한 교차 격자 편집"이 핵심이라 중복이 없습니다.
- **B010 — Comparison / Diff View 템플릿 (버전·이력 비교)**: 두 버전·레코드를 좌우로 나란히 비교하고 추가/삭제/수정을 강조 표시하는 대조 레이아웃이 부재. ERP 문서 개정 비교, 계약·사양서 버전 대조, 승인 전후 값 비교에 재활용도가 높습니다. MasterDetail(목록+단건 상세)·DetailView(단건 조회)와 달리 "두 대상의 필드 단위 차이 강조"가 핵심이라 목적이 구분됩니다.

공통 근거:

- 세 항목 모두 기존 `src/templates/business/` 17종(ActivityTimeline·ApprovalView·DashboardKPI·DetailView·DocumentCatalog·FileExplorer·FormRegister·GlobalSearchResults·InboxCenter·KanbanBoard·ListSearchTable·MasterDetail·MonitoringBoard·ReportLayout·ScheduleCalendar·SettingsPage·WizardForm)과 목적이 겹치지 않아 정책 2항(DRY)에 위배되지 않습니다.
- 세 항목 모두 기존 디자인 토큰과 컴포넌트(Table, Stepper, Select, Checkbox, Tag, StatusBadge, Avatar, Card, Grid, Divider, Stack 등)만으로 재구현 가능하여 정책 4항(신규 의존성 금지)을 준수합니다.
- 세 항목 모두 소비자용 마케팅 트렌드가 아닌 내부 업무 시스템 패턴(데이터 적재·권한 관리·버전 비교)이라 정책 3항(적합성)에 부합합니다.

### B008 — Templates/Business "Data Import Mapping" (export: DataImport)

- 벤치마크: Flatfile (https://flatfile.com)
- 벤치마크 스크린샷(자리표시자, 접근 차단): `docs/loop/screenshots/2026-07-18-B008-benchmark.png`
- 자사 스크린샷: `docs/loop/screenshots/2026-07-18-B008-ours.png`
- 소견(참고용 — 최종 판단 아님): 자사 화면은 업로드→컬럼 매핑→검증 미리보기→완료의 4단계 스테퍼를 상단에 명확히 노출하고, 컬럼 매핑 표에 "필수" 태그와 드롭다운으로 원본 컬럼↔시스템 필드 대응을 직관적으로 보여줍니다. 검증 미리보기 섹션에서 정상/경고/오류 상태를 뱃지 색상으로 구분한 점은 Flatfile류 데이터 임포트 툴의 핵심 UX(매핑 confidence 표시, 행 단위 오류 하이라이트)와 방향이 일치합니다. 다만 벤치마크 화면을 직접 확인하지 못해, 오류 행에 대한 인라인 수정(예: 셀 편집) 기능 유무 등 세부 상호작용 비교는 이번 검증에서 제외되었습니다.

### B009 — Templates/Business "Permission Matrix" (export: Permission)

- 벤치마크: GitHub Docs - Roles in an organization (https://docs.github.com/en/organizations/managing-peoples-access-to-your-organization-with-roles/roles-in-an-organization)
- 벤치마크 스크린샷(자리표시자, 접근 차단): `docs/loop/screenshots/2026-07-18-B009-benchmark.png`
- 자사 스크린샷: `docs/loop/screenshots/2026-07-18-B009-ours.png`
- 소견(참고용 — 최종 판단 아님): 자사 화면은 리소스(OMS·WMS·PRM)를 행 그룹으로 묶고, 역할(관리자·매니저·실무자·파트너사)을 열로 배치한 뒤 인원 수를 함께 표기해 매트릭스의 맥락 정보를 보강했습니다. GitHub 조직 역할 문서가 역할별 권한을 표 형태로 정리하는 방식과 구조적으로 유사한 접근입니다. 다만 GitHub 문서 원문은 텍스트 표(읽기 전용 설명)에 가깝고 자사 화면은 체크박스 편집 그리드라는 차이가 있어, 이 부분은 "참고 대상 자체가 정적 문서 vs 편집 UI"라는 성격 차이로 이해할 필요가 있습니다.

### B010 — Templates/Business "Comparison Diff View" (export: Comparison)

- 벤치마크: GitHub Compare (facebook/react) (https://github.com/facebook/react/compare)
- 벤치마크 스크린샷(자리표시자, 접근 차단): `docs/loop/screenshots/2026-07-18-B010-benchmark.png`
- 자사 스크린샷: `docs/loop/screenshots/2026-07-18-B010-ours.png`
- 소견(참고용 — 최종 판단 아님): 자사 화면은 좌우 2열(버전 1 vs 버전 2)로 필드를 나열하고, 변경된 필드마다 "수정/추가/삭제" 태그를 부착해 변경 유형을 한눈에 구분되게 했습니다. GitHub Compare가 좌우 브랜치를 나란히 놓고 추가(초록)/삭제(빨강) 라인을 강조하는 방식과 목적이 유사합니다. 다만 GitHub Compare는 라인 단위 diff(코드) 중심이고 자사 화면은 필드 단위 diff(구조화 데이터) 중심이라는 근본적 차이가 있어, 색상 강조(추가=초록/삭제=빨강 등 시각적 관례) 적용 여부는 벤치마크 실물 확인 후 추가 검토가 필요합니다.
