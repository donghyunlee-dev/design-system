현재 cursor 값은 5이고 표에 10개 행(BM01~BM10)이 있으므로, 0-based 인덱스 5번째 행인 **BM06 — Zendesk Help Center**(https://support.zendesk.com/hc/en-us, 패턴: 문서/FAQ)를 오늘의 벤치마크로 선택했습니다. 직전 사이클(2026-08-20)이 BM05를 소비하고 cursor를 5로 갱신한 순회의 다음 항목에 해당합니다.

선택 처리 후 benchmark-suite의 cursor 값을 (5 + 1) % 10 = **6**으로 갱신했습니다(다음 사이클은 BM07 Figma Community 홈).

정책 3항에 따라 이 페이지가 기간계(business/admin)와 일반 웹사이트(service) 중 어느 축에 해당하는지 먼저 판단합니다. Zendesk Help Center는 상단 검색 히어로 + 카테고리 카드/섹션 + 인기 문서(FAQ) 목록으로 구성된 문서/FAQ 지식베이스 패턴으로, 외부 사용자가 셀프서비스로 도움말을 찾도록 유도하는 서비스 성격이 강합니다. 다만 사내 기간계에서도 내부 매뉴얼·업무 도움말 센터로 재활용 여지가 있어, 재현·평가 단계에서 두 축 중 어느 쪽으로 재현할지 정책 3항 기준으로 확정합니다.

재현·평가 단계에서 기존 `src/components/`와 `src/templates/`의 문서/네비게이션·검색 결과 계열(Stripe Docs 홈, DocumentCatalog, Global Search Results 등 과거 사이클에서 다룬 문서·검색 템플릿 포함)을 대조해, 정책 2항(중복 금지)에 따라 목적이 겹치는 신규 템플릿은 추가하지 않습니다. 발견된 부족 항목은 정책 8항 기준으로 design-system-gap(구조적 부재)과 execution-issue(실행 품질 이슈)로 구분해, design-system-gap만 시스템 업그레이드 후보로 삼고 execution-issue는 리포트에만 기록합니다.

## 재현 (회귀 사이클)

`docs/loop/benchmark-suite.md`는 10개 항목을 한 바퀴 순회한 뒤 처음부터 다시 도는 회귀 테스트 목록이며(정책 7항), BM06 Zendesk Help Center는 2026-08-03 사이클(PR #39)에서 이미 `src/templates/business/HelpCenter.tsx`(홈: 검색 히어로 + ERP/OMS/WMS/PRM/계정·권한/그룹웨어 카테고리 카드 + FAQ 아코디언 + 문의 채널)와 `src/templates/business/HelpArticleView.tsx`(상세: 브레드크럼 → 제목/메타 → 본문 → 우측 고정 목차 → 투표 위젯 → 관련 문서)로 재현이 완료된 상태였습니다. 정책 2항(중복 금지)에 따라 동일 목적의 신규 템플릿은 추가하지 않고, 기존 두 템플릿과 스토리(`Templates/Business` / `Help Center`, `Help Article`)를 그대로 재사용합니다.

2026-08-03 리포트가 execution-issue로 남겨둔 3건 중, 컴포넌트 추가 없이 `HelpArticleView` 자체 상태 관리만으로 해소 가능한 항목을 이번 회귀 사이클에서 보완했습니다(신규 템플릿 아님, 기존 템플릿에 대한 외과수술식 보강):

1. **TOC 스크롤 하이라이트** — 본문 헤딩을 `IntersectionObserver`로 관찰해 현재 보고 있는 섹션을 우측 "이 문서에서" 목차에서 강조(`text-brand font-medium`)하도록 `activeSectionId` 상태를 추가했습니다.
2. **상단 지속 검색바 재사용** — `HelpCenter`와 동일한 `Input` 검색 패턴을 `searchValue`/`onSearchChange`/`onSearch` optional prop으로 노출해, 전달 시 상세 페이지 상단에도 검색창이 나타나도록 했습니다.
3. **하단 추가 문의 CTA 재사용** — `HelpCenter`에서 export된 `HelpContactChannel` 타입을 그대로 import해(타입 중복 정의 없음) `contactChannels` optional prop을 추가하고, `HelpCenter`와 동일한 Card/Tag/Button 조합으로 본문 하단에 문의 채널 카드를 배치했습니다.

세 항목 모두 기존 토큰·컴포넌트(`Input`, `Card`, `Tag`, `Button`, `Grid`)만 사용했고 신규 npm 패키지·신규 컴포넌트 파일을 추가하지 않았습니다. `Templates/Business` / `Help Article` 스토리를 위 세 prop을 사용하도록 갱신했습니다.

### 갭 목록

1. **[execution-issue] 작성자 아바타 미사용** — `src/components/foundation/Avatar.tsx`가 이미 존재하지만 `HelpArticleView.tsx`의 작성자 표기(`author`)는 텍스트만 사용하고 Avatar를 활용하지 않음.

3. **[design-system-gap] 댓글/토론(스레드) 컴포넌트 부재** — `src/components/{data,feedback,overlay,form,navigation,layout,chart}`, `src/templates` 전체를 확인했으나 사용자 댓글이나 토론 스레드를 표현할 컴포넌트/템플릿이 없음. 현재는 단순 "도움이 됐어요/안 됐어요" 이진 피드백만 제공.
4. **[execution-issue] 시각적 포인트(아이콘) 부재로 인한 밋밋한 톤** — `Icon` 컴포넌트가 존재함에도 관련 문서·문의 채널 카드 등에 아이콘을 전혀 사용하지 않아 정보 밀도만 있고 시각적 리듬이 부족함.
