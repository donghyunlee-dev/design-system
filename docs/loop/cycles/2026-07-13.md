## 오늘의 스코프

오늘 사이클 시작 시점 백로그에는 status가 "대기"인 항목이 없었습니다(B001~B004 모두 완료). 따라서 정책 5항 및 태스크 5단계, 그리고 직전 2026-07-11 사이클의 선례에 따라 기존 `src/components`, `src/templates` 커버리지 갭을 분석해 신규 pm-proposed 항목 3개를 백로그에 먼저 등록한 뒤 일일 스코프 상한(1~3개) 내에서 모두 진행합니다.

선정한 항목:

- **B005 — Notification / Inbox Center 템플릿 (알림·메시지함)**: 알림·요청·메시지를 읽음/안읽음 상태로 모아 일괄 처리하는 인박스 레이아웃이 부재. ERP(Enterprise Resource Planning) 알림, 승인 요청 알림, 그룹웨어·팀즈(Microsoft Teams) 메시지 인박스 등 내부 업무 시스템 재활용도가 가장 높다고 판단해 최우선 선정. 기존 ApprovalView(단건 승인)·ActivityTimeline(단일 대상 시간순 이력)과 목적이 명확히 구분됩니다.
- **B006 — File Manager / Document Explorer 템플릿 (자료실·첨부 탐색기)**: 폴더·파일을 브레드크럼 경로와 목록/그리드로 탐색하고 파일 액션을 수행하는 자료실 레이아웃이 부재. WMS(Warehouse Management System) 문서, ERP 첨부, 계약·매뉴얼 자료실에 재활용도가 높음. DocumentCatalog(목차+본문 열람)와 달리 파일/폴더 탐색·관리가 목적이라 중복이 없습니다. B001 조사 시 범위 밖으로 남긴 File Explorer 패턴에 해당해 갭 근거가 명확합니다.
- **B007 — Global Search Results 템플릿 (통합 검색 결과)**: 여러 엔티티(주문·파트너·문서 등)를 가로지르는 통합 검색 결과를 좌측 패싯 필터 + 그룹화된 결과 목록으로 표시하는 레이아웃이 부재. ERP·OMS(Order Management System)·WMS 통합 검색에 재활용 가능. ListSearchTable(단일 엔티티 필터 테이블)과 달리 크로스-엔티티 그룹 결과가 목적이라 중복이 없습니다.

공통 근거:

- 세 항목 모두 기존 `src/templates/business/`(목록·상세·폼·대시보드·모니터링·승인·설정·리포트·마스터디테일·마법사폼·문서카탈로그·칸반·타임라인·일정)와 목적이 겹치지 않아 정책 2항(DRY)에 위배되지 않습니다.
- 세 항목 모두 기존 디자인 토큰과 컴포넌트(List, Card, Tag, StatusBadge, Avatar, Breadcrumb, DropdownMenu, Table, Grid, Divider, Stack 등)만으로 재구현 가능하여 정책 4항(신규 의존성 금지)을 준수합니다.
- 세 항목 모두 소비자용 트렌드가 아닌 내부 업무 시스템 패턴이라 정책 3항(적합성)에 부합합니다.

## PM 방향 제안 로그

신규 제안 3건(B005, B006, B007)을 backlog.md에 source: pm-proposed로 등록한 뒤 오늘 스코프에 포함했습니다.

- 근거: 커버리지 갭 분석 결과, 내부 업무 시스템에서 빈번한 3개 패턴(알림·메시지 인박스 / 파일·자료실 탐색기 / 통합 검색 결과)이 기존 14종 business 템플릿에 존재하지 않음을 확인했습니다. 즉흥 진행을 피하기 위해 백로그에 먼저 등록한 후 진행중 상태로 전환했습니다.
- 우선순위: B005 > B006 > B007 (내부 시스템 재활용 빈도 기준). 3건 모두 일일 상한(3개) 이내이며 신규 의존성 없이 기존 컴포넌트 조합으로 구현 가능합니다.
- 각 항목별 품질 비교 벤치마크(참고용, 코드 복사 아님 — 레이아웃/구조만 참고):
  - B005: GitHub Notifications (https://github.com/notifications) — 읽음/안읽음, 유형·저장소별 필터, 일괄 처리 액션을 갖춘 대표적 알림 인박스 UI.
  - B006: Google Drive (https://drive.google.com) — 브레드크럼 경로 + 목록/그리드 전환 + 파일 액션 메뉴를 갖춘 대표적 파일 관리 UI.
  - B007: GitHub Search Results (https://github.com/search) — 좌측 패싯 필터 + 유형별 그룹화된 결과 목록을 갖춘 대표적 통합 검색 결과 UI.

### B005 — Templates/Business · Inbox Center

- 벤치마크: GitHub Notifications (https://github.com/notifications)
- 스크린샷: `docs/loop/screenshots/2026-07-13-B005-ours.png` / `docs/loop/screenshots/2026-07-13-B005-benchmark.png`
- 소견(참고용 — 최종 판단 아님): 벤치마크 URL은 로그인이 필요해 실제로는 GitHub 로그인 화면이 캡처되었습니다(비로그인 상태에서 벤치마크 레이아웃 자체를 확인하지 못함). 우리 쪽 Inbox Center는 안읽음 점 표시, 유형 태그(ERP 승인/그룹웨어/팀즈/WMS 재고), 전체·안읽음 탭, 일괄 읽음 처리 액션을 갖춰 기획 의도상 참고했던 알림함 패턴(읽음 상태 구분 + 필터 + 일괄 처리)은 구조적으로 구현되어 있습니다. 다만 실제 GitHub UI와의 시각적 대조는 이번 캡처로는 불가능해 별도 로그인 세션 확보 후 재비교가 필요합니다.

### B006 — Templates/Business · File Explorer

- 벤치마크: Google Drive (https://drive.google.com)
- 스크린샷: `docs/loop/screenshots/2026-07-13-B006-ours.png` / `docs/loop/screenshots/2026-07-13-B006-benchmark.png`
- 소견(참고용 — 최종 판단 아님): drive.google.com 접속 시 로그인 없이는 실제 파일 탐색기 UI가 아닌 Google Drive 마케팅 소개 페이지로 리다이렉트되어, 목록/그리드 전환이나 실제 파일 액션 메뉴의 시각적 비교는 이번 캡처로 확인할 수 없었습니다. 우리 쪽 File Explorer는 브레드크럼(자료실 / 계약·매뉴얼), 목록/격자 전환 토글, 파일 유형 배지(폴더/PDF/XLSX/DOCX), 크기·수정일·소유자 컬럼, 행별 더보기(⋯) 메뉴를 갖춰 기획 시 참고한 "브레드크럼 + 목록/그리드 + 파일 액션" 구조는 반영되어 있습니다. 실제 Drive 파일 목록 화면과의 밀도·정렬 방식 대조는 로그인 세션 확보 후 재검증이 필요합니다.

### B007 — Templates/Business · Global Search Results

- 벤치마크: GitHub Search Results (https://github.com/search?q=react&type=repositories)
- 스크린샷: `docs/loop/screenshots/2026-07-13-B007-ours.png` / `docs/loop/screenshots/2026-07-13-B007-benchmark.png`
- 소견(참고용 — 최종 판단 아님): 이 항목은 로그인 없이 벤치마크 UI가 정상적으로 캡처되었습니다. GitHub 검색 결과는 좌측에 결과 유형(Repositories/Issues/Pull requests 등)과 언어·소유자 등 상세 패싯 필터를 세로로 나열하고, 우측에 카드형 결과 목록과 우측 사이드바(관련 정보/추천)를 배치합니다. 우리 쪽 Global Search Results는 좌측에 유형(주문/파트너/문서)과 시스템(ERP/OMS/WMS) 패싯 카운트를 표시하고, 우측에 유형별로 그룹화된 결과 카드를 배치해 전체적인 "좌측 패싯 + 우측 그룹 결과 목록" 골격은 유사합니다. 차이점으로는 GitHub는 페이지네이션과 정렬 드롭다운, 결과 건수·응답시간 표기가 있는 반면 우리 쪽은 전체 건수만 상단에 표시하고 페이지네이션·정렬 UI가 없어, 결과 건수가 많은 시나리오에 대한 대응이 상대적으로 단순합니다.
